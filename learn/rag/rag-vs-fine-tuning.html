    RAG vs fine-tuning: which one for your documents?

    Use RAG when the model needs facts from your documents, and fine-tuning when it needs a behaviour: a format, a style, a task, or reading passages more reliably. Fine-tuning on question-answer pairs rarely installs the facts themselves; it teaches what answers from the documents sound like. On IRS Publication 17, BrewSLM's published run scored a 3B base model 0.17 alone, 0.73 with retrieved passages and 0.02 after fine-tuning on 405 question-answer pairs, while a later fine-tune that taught a 1.5B model to read retrieved passages beat the same model reading them untrained, 0.688 against 0.570 for the published seed (+0.07 to +0.12 across three seeds).

    Runs on: CPU, about four minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · pypdf 5.1.0 · numpy 2.1.3 · Ollama 0.32.9 · qwen2.5:1.5b-instruct (Q4_K_M) · CPU (20-core Arm, no GPU)

    Facts go in the prompt, behaviour goes in the weights

    The two are often presented as rivals. They solve different problems.

    • RAG changes what the model sees. Retrieved passages put the relevant facts in the prompt for each question. Nothing is trained, an updated document is live as soon as it is re-indexed, and every answer can point at its source.
    • Fine-tuning changes how the model behaves. It is good at formats (always return this JSON), tone, narrow tasks (classify, extract, tag) and skills such as reading a passage carefully. It is poor at storing hundreds of specific facts from a few hundred examples, and what it stores can't be updated without training again.

    So the useful question is rarely "RAG or fine-tuning?" but "does the base model with my documents in the prompt already do the job, and if not, is the gap about facts or about behaviour?"

    What BrewSLM measured on IRS Publication 17

    Two published runs on the same 142-page publication, each judged by a local model grading answers against an answer key (correct 1, partial 0.5, wrong 0):

    SystemJudge scoreSource
    Qwen2.5-3B-Instruct alone (41 questions)0.17Part 1
    Same model + retrieved passages0.73
    Fine-tuned on 405 question → answer pairs (run #148)0.02
    Qwen2.5-1.5B-Instruct alone (157 questions)0.073Part 2
    Same model + retrieved passages (the bar)0.570
    Fine-tuned to read passages, + the same passages (run #162)0.688
    The same fine-tune, no passages0.185

    The first fine-tune learned the publication's register and lost its facts: token F1 doubled while judged correctness fell to 0.02. The second worked because it was trained on prompts that included retrieved passages, so it learned a behaviour, reading, rather than the facts. Without passages it still scored only 0.185; retrieval kept doing the remembering. The 0.73 is the best of nine retrieval settings picked on the same 41 questions, and the reader's gain ranged from about +0.07 to +0.12 across three training seeds; both posts give the intervals.

    Updating a fact without training

    One property is easy to test on a laptop: when the document changes, RAG follows it. The test below takes the questions whose answer key is a number, changes that number in the publication's text (as a new edition would), rebuilds only the affected chunks' embeddings, and asks the same questions again. Set up:

    pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
pip install sentence-transformers==3.3.1 transformers==4.46.3 tokenizers==0.20.3 \
    huggingface_hub==0.36.2 pypdf==5.1.0 numpy==2.1.3
ollama pull qwen2.5:1.5b-instruct

    The corpus, chunks and frozen questions are shared with the other RAG pages:

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    import time
import numpy as np
from sentence_transformers import SentenceTransformer

keys = json.load(open("pub17-answer-keys.json"))["keys"]
embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                               revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
flat = lambda s: " ".join(s.split())
numbers = lambda s: {x.replace(",", "") for x in re.findall(r"\d[\d,]*\d|\d", s)}

def answer(question, chunk_list, index):
    ids = np.argsort(-(index @ embedder.encode(question, normalize_embeddings=True)))[:5]
    passages = "\n\n".join(f"[{n}] {flat(chunk_list[j])}" for n, j in enumerate(ids, 1))
    return chat("Answer the question using only the passages below, in one or two sentences. "
                f"If they don't contain the answer, say so.\n\n{passages}\n\nQuestion: {question}")

# questions whose key is a number that appears in the evidence span
edits = []
for q in qs:
    for k in keys.get(q["id"], []):
        m = re.search(r"\d[\d,]*", k)
        if m and m.group(0) in q["evidence"]:
            old = m.group(0)
            new = str(int(old[0]) % 9 + 1) + old[1:]          # 420 -> 520: same length
            edits.append((q, old, new))
            break
new_text = text
for q, old, new in edits:                                     # change the number inside every evidence occurrence
    new_text = new_text.replace(q["evidence"], q["evidence"].replace(old, new, 1))
assert len(new_text) == len(text)
new_chunks = recursive_split(new_text, 512)
changed = [j for j, (a, b) in enumerate(zip(chunks, new_chunks)) if a != b]
print(len(edits), "questions with a numeric key;", len(changed), "chunks changed")

t0 = time.time()
index = embedder.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
new_index = index.copy()
new_index[changed] = embedder.encode([new_chunks[j].strip() for j in changed], normalize_embeddings=True)
print(f"re-embedded {len(changed)} chunks in {time.time() - t0:.0f} s (the whole index, then the changed rows)")

counts = {"original": [0, 0], "edited": [0, 0]}                # [says the old number, says the new number]
for q, old, new in edits:
    for name, ch, idx in (("original", chunks, index), ("edited", new_chunks, new_index)):
        said = numbers(answer(q["question"], ch, idx))
        counts[name][0] += old.replace(",", "") in said
        counts[name][1] += new.replace(",", "") in said
print("\n                 says old number   says new number   (of", len(edits), "questions)")
for name, (o, n) in counts.items():
    print(f"{name + ' text':<16} {o:>15}   {n:>15}")

                 says old number   says new number   (of 23 questions)
original text                 15                 0
edited text                    7                11
    • The edit went live without training. Before the edit, 15 of 23 answers gave the publication's number. After changing one digit in 26 chunks and re-embedding them, which took seconds, 11 answers gave the edited number. A fine-tuned model would keep giving the old number until it was trained again.
    • The flip side is the same property. The model repeated numbers that were planted, not true. RAG is as right as the passages it retrieves; a stale or wrong document produces confident, faithful, wrong answers. That is why faithfulness and correctness are measured separately.
    • Not every question followed. 7 answers still gave the old number after the edit. This page didn't break them down; possible causes are an unedited chunk elsewhere stating the same figure (a table repeating it, say) and the model's own memory.

    Limits: one 1.5B model on CPU, 23 questions, one-digit edits in numbers only, and a crude check (is the number among the numbers in the answer?) that ignores what else the answer says. This page doesn't fine-tune anything; the fine-tuning numbers above are BrewSLM's published runs on a GPU, not reruns.

    Choosing, in practice

    If the problem is…Start withWhy
    Facts from your documentsRAGFacts stay current and citable; no training run.
    Output format, schema, tonePrompting, then fine-tuningBehaviour learns well from a few hundred examples.
    A narrow task (classify, extract, tag)Fine-tuning a small modelCheap to serve, and the labels define the task.
    RAG answers wrong with the right passage retrievedFine-tune to read passagesThe gap is reading, a behaviour (BrewSLM's part 2).
    RAG answers wrong because the passage wasn't retrievedFix retrievalNo fine-tune can read a passage it never sees.

    Pitfalls

    • Reporting the wrong metric. Run #148's token F1 rose from 0.13 to 0.27 while judged correctness fell from 0.20 to 0.02 (part 1). Word overlap rewards sounding like the source.
    • The wrong bar for a fine-tune. A reader fine-tune compared with the base model without passages looks tenfold better (0.073 to 0.688); compared with the base model reading the same passages, it is +0.118 (part 2). The second is the honest comparison.
    • Licences. BrewSLM's part 2 moved from a 3B to a 1.5B base because the 3B's research-only licence doesn't allow publishing a fine-tune (part 2). Check before you train, not after.
    • Training on facts that change. A fine-tune freezes this year's figures; the edit test above shows retrieval picking up a change in seconds.

    In BrewSLM: the documents → Q&A flow scores the base model with and without your passages before it trains, and offers to reroute the project to RAG when retrieval already answers.

    Practice

    1. A support bot must answer from a 300-page manual that changes monthly, in a fixed JSON format. RAG, fine-tuning, or both?

    Both, for different jobs: RAG for the manual's facts, since they change monthly; prompting first and then, if needed, a small fine-tune for the JSON format. Measure the base model with retrieval before training anything.

    2. Why did fine-tuning on 405 question-answer pairs make the model worse at the facts?

    405 pairs drawn from 150 of 1,064 passages can't install the other passages' facts, and training on them shifted the model towards the publication's style while degrading what it already knew. It learned how answers sound, not which way the facts point.

    3. What is the right baseline for a fine-tune that answers from retrieved passages?

    The same base model, with the same retrieved passages, on the same held-out questions, scored the same way. Anything weaker credits retrieval's gain to the fine-tune.
