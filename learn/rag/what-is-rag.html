    What is RAG? Retrieval-augmented generation in one example

    Retrieval-augmented generation (RAG) answers a question in two steps: first retrieve the passages from your documents that look most relevant, then put them in the prompt and have a language model answer from them. The model doesn't need to have learned your documents; it only has to read the passages it is handed, which is why RAG works with small models and stays current when the documents change. On 47 questions about IRS Publication 17, a 1.5B model running on CPU gave the expected answer to 8 on its own, to 30 with the top five passages from a simple embedding search, and to 41 with better-ranked passages (both gains clear in paired tests).

    Runs on: CPU, about fifteen minutes for every block on the page once the models are downloaded (most of it the 141 model calls) Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · Ollama 0.32.9 · qwen2.5:1.5b-instruct (Q4_K_M) · CPU (20-core Arm, no GPU)

    The two steps

    1. Retrieve. Your documents are cut into chunks ahead of time and indexed. At question time a retriever (keyword search such as BM25, an embedding search, or both) returns the few chunks that best match the question.
    2. Generate. The chunks go into the prompt with an instruction such as "answer using only these passages", and a language model writes the answer.

    Nothing is trained. The model's knowledge of tax law doesn't matter much; its ability to read does. That has three consequences worth knowing before you build one:

    • Retrieval sets the ceiling. If the passage with the answer isn't retrieved, the model either says it can't answer or answers from memory, often wrongly.
    • Updating is re-indexing. When the document changes, rebuild the index; no model changes. The RAG vs fine-tuning page measures what that buys.
    • You can check the answer against the source. The passages are right there, which makes citations and faithfulness checks possible.

    A whole RAG pipeline in plain Python

    No framework: pypdf for the text, the chunking page's splitter, sentence-transformers for the embeddings, and a 1.5B instruction model served by Ollama on CPU. Qwen2.5-1.5B-Instruct is Apache-2.0 licensed. Set up:

    pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
pip install sentence-transformers==3.3.1 transformers==4.46.3 tokenizers==0.20.3 \
    huggingface_hub==0.36.2 rank-bm25==0.2.2 pypdf==5.1.0 numpy==2.1.3
ollama pull qwen2.5:1.5b-instruct     # about 1 GB; then `ollama serve` if it isn't running

    First the documents: IRS Publication 17 (2025), the IRS's 142-page guide to individual income tax, cut into 512-character chunks, with the 80 frozen questions every RAG page here uses.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Output

    sha256: 2d2381d62c7c77ed | chunks: 2170 | questions: 80 | with a relevant chunk: 79

    Then the model. This block also prints the model's digest, so a different build of the same tag shows up as a changed output:

    import json, os, urllib.request

host = os.environ.get("OLLAMA_HOST", "127.0.0.1:11434")      # where `ollama serve` listens
OLLAMA = host if host.startswith("http") else "http://" + host
MODEL = "qwen2.5:1.5b-instruct"                              # `ollama pull qwen2.5:1.5b-instruct`

def chat(prompt, num_predict=120, num_ctx=4096):
    body = {"model": MODEL, "messages": [{"role": "user", "content": prompt}], "stream": False,
            "keep_alive": 0,                                 # unload after each call, so no cached prompt carries over
            "options": {"temperature": 0, "seed": 0, "num_ctx": num_ctx, "num_predict": num_predict,
                        "num_thread": 10}}                   # fastest on this machine; adjust for yours
    req = urllib.request.Request(OLLAMA + "/api/chat", json.dumps(body).encode(), {"Content-Type": "application/json"})
    return json.load(urllib.request.urlopen(req, timeout=900))["message"]["content"].strip()

tags = json.load(urllib.request.urlopen(OLLAMA + "/api/tags"))
print(MODEL, "digest", next(m["digest"][:12] for m in tags["models"] if m["name"] == MODEL))

    Output

    qwen2.5:1.5b-instruct digest 65ec06548149

    Now the pipeline itself: index once, then retrieve and generate per question.

    import numpy as np
from sentence_transformers import SentenceTransformer

embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                               revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
index = embedder.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)

def retrieve(question, k=5):
    q = embedder.encode(question, normalize_embeddings=True)
    return list(np.argsort(-(index @ q))[:k])

def rag_prompt(question, ids):
    passages = "\n\n".join(f"[{n}] " + " ".join(chunks[j].split()) for n, j in enumerate(ids, 1))
    return ("Answer the question using only the passages below, in one or two sentences. "
            f"If they don't contain the answer, say so.\n\n{passages}\n\nQuestion: {question}")

def closed_book_prompt(question):
    return f"Answer this question about US federal income tax in one or two sentences.\n\nQuestion: {question}"

q = next(x for x in qs if x["id"] == "q50")["question"]
ids = retrieve(q)
print("Q:", q)
print("closed book:", chat(closed_book_prompt(q)))
print("retrieved chunks:", [int(j) for j in ids], "| prompt:", len(rag_prompt(q, ids)), "characters")
print("with RAG:   ", chat(rag_prompt(q, ids)))

    Output

    Q: How much per day can I exclude from long-term care insurance payments for 2025?
closed book: For the year 2025, you can exclude up to $1,370 of long-term care insurance payments from your taxable income.
retrieved chunks: [1144, 863, 795, 867, 787] | prompt: 2414 characters
with RAG:    You can generally exclude from gross income up to $420 a day for 2025.

    The publication says the 2025 limit is $420 a day. On its own the model offers a figure with no source; with the five retrieved chunks in the prompt it quotes the publication's number.

    Measured: closed book against RAG on 47 tax questions

    Answer keys. 47 of the 80 questions have a short, distinctive answer (a number, a form, a phrase such as "fair market value"). Their keys were written from the evidence spans before any model answered (pub17-answer-keys.json). An answer counts as right when, ignoring case and punctuation, it contains a key. This check is crude: it misses a right answer worded differently and passes a wrong one that mentions the key, so the answers from both retrieval arms were also read by hand (see the limits paragraph below).

    Arms. The model alone; the model with the top 5 chunks from the embedding search above; and the model with the top 5 after hybrid search and reranking, the best retrieval on the reranking page. Same prompts, temperature 0.

    import math, time
from rank_bm25 import BM25Okapi
from sentence_transformers import CrossEncoder

keys = json.load(open("pub17-answer-keys.json"))["keys"]
norm = lambda s: re.sub(r"[^a-z0-9]", "", s.lower())
right = lambda answer, qid: any(norm(k) in norm(answer) for k in keys[qid])
keyed = [i for i, x in enumerate(qs) if x["id"] in keys]

words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
bm25 = BM25Okapi([words(c) for c in chunks])
ce = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2", device="cpu", revision="233902d25c440f23af6f7d6e94d2946bac0bee0a")

def best_retrieve(question, k=5):
    """hybrid (BM25 + dense, RRF k=60) top 30, reranked by the cross-encoder"""
    qv = embedder.encode(question, normalize_embeddings=True)
    score = {}
    for ranking in (np.argsort(-bm25.get_scores(words(question)))[:100], np.argsort(-(index @ qv))[:100]):
        for r, j in enumerate(ranking, 1):
            score[j] = score.get(j, 0) + 1 / (60 + r)
    pool = sorted(score, key=lambda j: -score[j])[:30]
    ce_scores = ce.predict([(question, chunks[j]) for j in pool])
    return [pool[j] for j in np.argsort(-ce_scores)[:k]]

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, exact McNemar p = {p:.5f}"

arms = {"model alone": lambda x: closed_book_prompt(x),
        "+ dense top 5": lambda x: rag_prompt(x, retrieve(x)),
        "+ reranked top 5": lambda x: rag_prompt(x, best_retrieve(x))}
results, found = {}, {}
for name, make in arms.items():
    t0 = time.time()
    answers = [chat(make(qs[i]["question"])) for i in keyed]
    results[name] = [right(a, qs[i]["id"]) for a, i in zip(answers, keyed)]
    print(f"{name:<17} {sum(results[name]):>2} of {len(keyed)} match the key   ({(time.time() - t0) / len(keyed):.1f} s a question)")
for name, ids_of in (("+ dense top 5", retrieve), ("+ reranked top 5", best_retrieve)):
    found[name] = sum(bool(set(ids_of(qs[i]["question"])) & gold[i]) for i in keyed)
    print(f"answer passage retrieved, {name}: {found[name]} of {len(keyed)}")
print("dense RAG vs alone:   ", mcnemar(results["+ dense top 5"], results["model alone"]))
print("reranked vs dense RAG:", mcnemar(results["+ reranked top 5"], results["+ dense top 5"]))

    Output (times vary)

    model alone        8 of 47 match the key   (2.7 s a question)
+ dense top 5     30 of 47 match the key   (5.9 s a question)
+ reranked top 5  41 of 47 match the key   (9.5 s a question)
answer passage retrieved, + dense top 5: 35 of 47
answer passage retrieved, + reranked top 5: 41 of 47
dense RAG vs alone:    23 vs 1, exact McNemar p = 0.00000
reranked vs dense RAG: 12 vs 1, exact McNemar p = 0.00342
    • Retrieval did most of the work. The model alone matched 8 of 47 keys. With five chunks from a plain embedding search it matched 30: 23 questions gained, 1 lost (exact McNemar p < 0.00001; the output rounds it to 0.00000).
    • Better retrieval gave better answers. With the reranked chunks it matched 41 (12 gained, 1 lost, p = 0.003). The answer passage was in the prompt for 41 questions with reranking against 35 with dense search, so most of the answer gain follows from retrieval.
    • Retrieval isn't the whole story. Compare the "answer passage retrieved" lines with the matches: dense search put the answer passage in the prompt for 35 questions but the key matched for 30, so at least five answers missed with the passage in front of the model. That is a reading error, the kind the faithfulness page looks at.

    Limits: a crude key-string check on 47 short-answer questions, one small model, one document. The hand check is in the wave evidence notes. The counts were identical across two full runs on this machine, though single answers can change (see the closed-book line above), and they can differ on another CPU or Ollama version.

    Pitfalls

    • Measuring only the answer. When an answer is wrong you need to know whether retrieval missed or the model misread. In BrewSLM's Pub 17 run, 4 of 9 wrong answers were retrieval misses and 5 were misreadings (IRS Pub 17 post). Log the retrieved ids with every answer, as the block above does.
    • Scoring long answers by word overlap. Token F1 can rise while correctness falls; the IRS Pub 17 post found F1 doubling (0.13 to 0.27) on a run whose judged correctness fell from 0.20 to 0.02. Use answer keys or a judge that grades facts.
    • Temperature 0 is not enough for repeatable answers. Ollama keeps the last prompt's computed state and reuses any shared prefix. On this CPU that changed a temperature-0 answer with the previous request: in a side test not shown here, the closed-book answer to the question above came back as $1,000 after one earlier prompt and $10,000 after another. The chat function therefore sets keep_alive to 0, so the model is unloaded after each call (Ollama API docs). Even so, on this busy 20-core CPU the closed-book answer was $1,370 on one run and $10,000 on the next (the right figure is $420 a day), so the output above marks it as varying. The counts in the measurement matched across both runs.
    • Page furniture in the index. Repeated headers and footers end up in chunks, then in prompts and answers. 173 of 1,103 first-pass Pub 17 passages carried one in BrewSLM's run (IRS Pub 17 post). This page's cleaner only removes proof-sheet lines.

    Practice

    1. Your RAG system answers a question wrongly. What two things do you check, in which order?

    First whether the passage that holds the answer was retrieved (look at the logged ids against a labelled passage). If it wasn't, it's a retrieval problem: chunking, retriever, k. If it was, the model misread or ignored it: prompt, model size, or too many distracting passages.

    2. Why does RAG work with a 1.5B model that knows little tax law?

    Because the task becomes reading comprehension over a few hundred words in the prompt, not recall of facts from training. Small instruction models read short passages reasonably well; they recall specific figures poorly, as the 8 of 47 closed-book result shows.

    3. The key check says 41 of 47. Why might the real number be higher or lower?

    Higher: right answers worded differently from the key ("$420 per day" passes, "four hundred twenty dollars" doesn't). Lower: an answer that mentions the key while saying something wrong about it still passes. Read the answers, or use a judge, before quoting the number.
