    BM25 explained: keyword retrieval in Python

    BM25 scores a passage by the query words it contains, giving rare words more weight (IDF), giving repeats of a word less and less extra credit (k1) and discounting long passages (b). It needs no model and no GPU, so it is the baseline every RAG retriever should be compared with. On 80 questions about IRS Publication 17, plain BM25 put the answer passage in the top 5 for 56; dropping 39 common words such as "can", "my" and "does" raised that to 63 (suggestive, p = 0.065), while no k1 or b setting moved it by more than four.

    Runs on: CPU, under a minute for every block on the page Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    How BM25 scores a passage

    For each query word that appears in a passage, BM25 adds one term, and the passage's score is the sum. Each term is the product of two parts.

    • IDF, how rare the word is. A word in almost every passage ("the", "tax" in a tax guide) tells you little; a word in three passages ("kidnapped") tells you a lot. With N passages and the word in df of them, the usual form is log(1 + (N − df + 0.5) / (df + 0.5)).
    • Term frequency, saturated. A word that appears twice counts more than once, but not twice as much: tf × (k1 + 1) / (tf + k1 × L), where L is the passage length relative to the average. k1 sets how fast repeats stop helping (1.2 to 2 is usual), and b (usually 0.75) sets how much a long passage is discounted through L = 1 − b + b × length / average length.

    That is the whole method: no training, no vectors, and an index that is a table of word counts. What it can't do is match words that aren't there. A question that says "deduct" will not match a passage that says "deductible" unless the tokenizer makes them the same word.

    BM25 from scratch, next to rank-bm25

    Fifteen lines of plain Python, run on three short passages and a question, then the same input through the rank-bm25 package. Install what this page uses:

    pip install rank-bm25==0.2.2 pypdf==5.1.0 numpy==2.1.3
    import math
from collections import Counter

def bm25_scores(query, docs, k1=1.5, b=0.75):
    N = len(docs)
    avgdl = sum(map(len, docs)) / N
    df = Counter(w for d in docs for w in set(d))
    scores = []
    for d in docs:
        tf, s = Counter(d), 0.0
        for w in query:
            if tf[w]:
                idf = math.log(1 + (N - df[w] + 0.5) / (df[w] + 0.5))
                s += idf * tf[w] * (k1 + 1) / (tf[w] + k1 * (1 - b + b * len(d) / avgdl))
        scores.append(s)
    return scores

docs = [d.split() for d in ["you can open a traditional ira at any time",
                            "a roth ira contribution is not deductible",
                            "the standard deduction for a single filer"]]
query = "can i deduct a traditional ira contribution".split()
print("from scratch:", [round(s, 3) for s in bm25_scores(query, docs)])

from rank_bm25 import BM25Okapi
bm = BM25Okapi(docs)
print("rank-bm25:   ", [round(float(s), 3) for s in bm.get_scores(query)])
print("rank-bm25 idf:", {w: round(float(bm.idf[w]), 3) for w in query if w in bm.idf})

    Output

    from scratch: [2.379, 1.649, 0.139]
rank-bm25:    [1.104, 0.707, 0.088]
rank-bm25 idf: {'can': 0.511, 'a': 0.084, 'traditional': 0.511, 'ira': 0.084, 'contribution': 0.511}

    Both rank the first passage top, but the numbers differ, and the last line shows why. BM25Okapi uses the older IDF, log((N − df + 0.5) / (df + 0.5)), which goes negative for a word in more than half the passages; the package then replaces it with a floor of 0.25 × the average IDF. "a" and "ira" each get that floor here, so "ira" counts for as little as "a". On three passages that is an artefact; on a real corpus it only touches very common words, but it means two "BM25" libraries can rank the same passages differently. Note also that "deduct" matched nothing: "deductible" and "deduction" are different tokens.

    Measured: tokenization, IDF and k1/b on IRS Publication 17

    The corpus and questions are the ones the chunking page used, so the numbers line up across the RAG pages. This block downloads IRS Publication 17 (2025), cleans the text, cuts it into 512-character chunks with the same recursive splitter, and loads 80 questions: the 30 from the chunking page and 50 more drafted the same way (with an AI assistant, while reading pages the first 30 don't use, and frozen in the repository before any retrieval ran on them; pub17-more-questions.json). A chunk is relevant when it holds the question's whole evidence span.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Setup. Three tokenizers: plain lowercase words; the same with 39 common words removed (a list written once before the first run and not changed after); and that plus a crude suffix strip. Two IDF forms: the package's, and the smoothed one from the code above in a faster inverted-index version. Then a k1 × b grid. Each cell counts the questions whose relevant chunk is in the top 5.

    import time
import numpy as np
from rank_bm25 import BM25Okapi

STOP = set("a an the of to in for on and or is are was be my i me do does can if it its at by with "
           "from as what which how when who this that am have has get".split())
plain = lambda s: re.findall(r"[a-z0-9]+", s.lower())
nostop = lambda s: [w for w in plain(s) if w not in STOP]
def stem(w):
    for suf in ("ing", "ed", "es", "s"):
        if len(w) > 4 and w.endswith(suf):
            return w[:-len(suf)]
    return w
stemmed = lambda s: [stem(w) for w in nostop(s)]

class SmoothBM25:
    """BM25 with the smoothed IDF, log(1 + (N - df + 0.5) / (df + 0.5)), over an inverted index."""
    def __init__(self, docs, k1=1.5, b=0.75):
        self.k1, self.b, self.N = k1, b, len(docs)
        self.dl = np.array([len(d) for d in docs], dtype=float)
        self.post = {}
        for i, d in enumerate(docs):
            for w, n in Counter(d).items():
                self.post.setdefault(w, ([], []))
                self.post[w][0].append(i)
                self.post[w][1].append(n)
    def get_scores(self, query):
        s, norm = np.zeros(self.N), self.k1 * (1 - self.b + self.b * self.dl / self.dl.mean())
        for w in query:
            if w in self.post:
                ids, tf = np.array(self.post[w][0]), np.array(self.post[w][1], dtype=float)
                idf = math.log(1 + (self.N - len(ids) + 0.5) / (len(ids) + 0.5))
                s[ids] += idf * tf * (self.k1 + 1) / (tf + norm[ids])
        return s

def hits(index, tok, k=5):
    return [bool(set(np.argsort(-index.get_scores(tok(q["question"])))[:k]) & gold[i]) for i, q in enumerate(qs)]

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c} questions only one found, exact McNemar p = {p:.3f}"

res = {}
print("tokenizer      rank-bm25  smoothed IDF   (top 5, of 80)")
for name, tok in (("plain", plain), ("no stop words", nostop), ("+ suffix strip", stemmed)):
    docs = [tok(c) for c in chunks]
    t0 = time.time()
    res[name] = hits(BM25Okapi(docs), tok)
    sec = (time.time() - t0) / len(qs) * 1000
    print(f"{name:<14} {sum(res[name]):>6}/80  {sum(hits(SmoothBM25(docs), tok)):>8}/80     {sec:.0f} ms a query")

print("\nk1 x b, rank-bm25, plain tokens:")
docs = [plain(c) for c in chunks]
for k1 in (0.5, 1.2, 1.5, 2.0):
    print(f"  k1={k1}: " + "  ".join(f"b={b}: {sum(hits(BM25Okapi(docs, k1=k1, b=b), plain))}"
                                    for b in (0.0, 0.5, 0.75, 1.0)))

print("\nno stop words vs plain:", mcnemar(res["no stop words"], res["plain"]))
bm = BM25Okapi(docs)
i = next(i for i, (a, b) in enumerate(zip(res["no stop words"], res["plain"])) if a and not b)
print("found only without stop words:", qs[i]["question"])
print("  plain top hit:", repr(" ".join(chunks[int(np.argmax(bm.get_scores(plain(qs[i]["question"]))))].split())[:75]))

  plain top hit: 'Y our compensation for official services to an international organization i'
    • The tokenizer mattered more than the parameters. Removing stop words took rank-bm25 from 56 to 63 of 80: nine questions were found only without them and two only with them (exact McNemar test, p = 0.065), suggestive rather than significant on 80 questions. Questions are full of "can I", "my" and "does", and in 512-character chunks of a tax guide those words still add score to passages that share nothing else with the question. The example above is typical: with "a", "has", "to" and "at" counted, a question about who must file came back with a passage about international organisations.
    • The suffix strip added two more (65), not tested for significance; it is a crude rule and can merge words that should stay apart.
    • The smoothed IDF added one or two in every row (57, 65, 67). The floor only touches words in more than half the chunks, so the gap is small, but the best cell on the page combines all three changes.
    • k1 and b moved recall by at most six questions across the whole grid (52 to 58), and the defaults (1.5, 0.75) gave 56. Tune them last.

    Limits: one document, 80 single-fact questions drafted with an AI assistant, and every setting is scored on the same questions it is compared on. There is no held-out set, so treat the best cell as slightly optimistic. Nothing on this page clears a significance test at 80 questions; the stop-word result comes closest.

    Pitfalls

    • "BM25" is a family, not one formula. rank-bm25's BM25Okapi floors negative IDF at 0.25 × the mean IDF (epsilon in its source), while Lucene and BrewSLM use the smoothed form. Scores are not comparable across libraries, and rankings can differ (toy example above).
    • Question words pollute the score. Natural questions carry "can I", "my", "does". On Pub 17 they cost 7 of 80 questions (measurement above). Strip them from the query, or rewrite the question into a keyword query (query rewriting).
    • No match without a shared token. "deduct" does not match "deductible", and "crypto" does not match "digital asset". That is the gap dense retrieval fills; see the dense retrieval page for which questions each one misses.
    • Form numbers split apart. [a-z0-9]+ turns "1099-DA" into "1099" and "da", and "1099" appears all over a tax guide. BrewSLM's tokenizer splits "1099-DA" the same way; its rule of keeping both the parts and the whole token applies to code identifiers (camelCase, snake_case) (auto_rag_service.py).

    In BrewSLM: retrieval starts from a hand-rolled BM25 (k1 1.5, b 0.75, smoothed IDF) that keeps stop words on purpose; on these questions dropping them looked better (p = 0.065), which BrewSLM's documents → Q&A sweep doesn't test.

    Practice

    1. With k1 = 0, what does BM25 become?

    The term-frequency part is tf × 1 / tf = 1 for any word present, so the score is the sum of the IDFs of the query words the passage contains. Repeats and passage length no longer matter, and b has no effect.

    2. A word appears in 1,500 of 2,170 chunks. What IDF does rank-bm25's BM25Okapi give it, and what does the smoothed form give?

    Okapi: log((2,170 − 1,500 + 0.5) / (1,500 + 0.5)) = log(0.447) ≈ −0.81, which is negative, so rank-bm25 replaces it with 0.25 × the average IDF. Smoothed: log(1 + 0.447) ≈ 0.37, small but positive.

    3. Your BM25 recall went from 56 to 58 of 80 after tuning k1. Should you ship the new value?

    Not on that evidence. Two questions in 80 is within noise, and you tuned on the questions you report. Check the discordant pairs with a paired test, and confirm on questions you didn't tune on. The tokenizer is the likelier win.
