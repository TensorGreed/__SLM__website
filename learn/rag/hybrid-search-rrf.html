    Hybrid search: combine BM25 and dense retrieval with RRF

    Hybrid search runs a keyword retriever (BM25) and a dense retriever on the same question and merges their rankings, so a passage either one ranks well can make the final list. Reciprocal rank fusion (RRF) does the merge with ranks alone: each passage scores the sum of 1 / (60 + rank) over the lists it appears in, with no score scaling to tune. On 80 questions about IRS Publication 17, RRF found the answer passage in the top 5 for 67, against 57 for dense alone and 56 for BM25 alone (paired tests, p = 0.013 for each gap).

    Runs on: CPU, about a minute for every block on the page once the model is downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    Why fuse two retrievers, and how RRF does it

    BM25 and dense retrieval fail on different questions. On the dense retrieval page they tied on totals (57 and 56 of 80 in the top 5) while 23 questions were found by only one of them. Hybrid search keeps both and merges the two ranked lists.

    The scores can't be added directly: a BM25 score of 14 and a cosine of 0.62 are on unrelated scales, and the BM25 scale changes with every query. Two common fixes:

    • Reciprocal rank fusion. Throw the scores away and keep the ranks. A passage at rank r in a list gets 1 / (k + r) from it, and its fused score is the sum over lists. k = 60 comes from the original RRF paper (Cormack, Clarke and Büttcher, SIGIR 2009) and damps the gap between rank 1 and rank 2.
    • Weighted score fusion. Rescale each list's scores to 0–1 for this query (min-max), then take α × dense + (1 − α) × BM25. It uses more information than ranks but adds α to tune and is sensitive to outliers in either list.

    RRF in ten lines

    Two toy rankings of passage ids. Passage c is second in both lists and wins after fusion, ahead of the passages each list put first. Install for the whole page:

    pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
pip install sentence-transformers==3.3.1 transformers==4.46.3 tokenizers==0.20.3 \
    huggingface_hub==0.36.2 rank-bm25==0.2.2 pypdf==5.1.0 numpy==2.1.3
    def rrf(rankings, k=60, top=None):
    """Reciprocal rank fusion: rankings is a list of ranked id lists, best first."""
    score = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=lambda d: -score[d])[:top]

bm25_list = ["a", "c", "d", "e"]
dense_list = ["b", "c", "e", "a"]
print("k=60:", rrf([bm25_list, dense_list]))
print("k=1: ", rrf([bm25_list, dense_list], k=1))

    Output

    k=60: ['c', 'a', 'e', 'b', 'd']
k=1:  ['a', 'c', 'b', 'e', 'd']

    With k = 60, c scores 2/62 ≈ 0.0323 and edges out a (1/61 + 1/64 ≈ 0.0320). With k = 1 a first place counts for much more: a, first in one list and fourth in the other, wins with 1/2 + 1/5 against 2/3. Ties keep the order the passages were first seen in.

    Measured: RRF and weighted fusion on IRS Publication 17

    Same setup as the other RAG pages: IRS Publication 17 (2025) in 512-character recursive chunks, 80 frozen questions (30 + 50), a chunk relevant when it holds the whole evidence span. q09's span is cut by a chunk boundary, so 79 is the ceiling.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Output

    sha256: 2d2381d62c7c77ed | chunks: 2170 | questions: 80 | with a relevant chunk: 79

    Setup. BM25 (rank-bm25 defaults, plain lowercase tokens) and all-MiniLM-L6-v2 at a pinned revision each rank every chunk. RRF fuses their top 100 with k from 1 to 200; weighted fusion min-max scales each query's full score lists and tries three values of α. The last row fuses dense with the stop-word-free BM25 from the BM25 page.

    import math
import numpy as np
from sentence_transformers import SentenceTransformer
from rank_bm25 import BM25Okapi

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
cos = model.encode([q["question"] for q in qs], normalize_embeddings=True) @ vecs.T
words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
STOP = set("a an the of to in for on and or is are was be my i me do does can if it its at by with "
           "from as what which how when who this that am have has get".split())
bm = BM25Okapi([words(c) for c in chunks])
bm_ns = BM25Okapi([[w for w in words(c) if w not in STOP] for c in chunks])
lex = np.array([bm.get_scores(words(q["question"])) for q in qs])
lex_ns = np.array([bm_ns.get_scores([w for w in words(q["question"]) if w not in STOP]) for q in qs])
rank = lambda scores: np.argsort(-scores, axis=1)
dense_r, lex_r, lexns_r = rank(cos), rank(lex), rank(lex_ns)

def found(ranked, k=5):
    return [bool(set(list(ranked[i])[:k]) & gold[i]) for i in range(len(qs))]

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.4f}"

def minmax(s):
    return (s - s.min(axis=1, keepdims=True)) / (s.max(axis=1, keepdims=True) - s.min(axis=1, keepdims=True))

runs = {"bm25": lex_r, "dense": dense_r}
for k in (1, 10, 60, 200):
    runs[f"rrf k={k}"] = [rrf([lex_r[i][:100], dense_r[i][:100]], k=k) for i in range(len(qs))]
for a in (0.3, 0.5, 0.7):
    runs[f"weighted a={a}"] = rank(a * minmax(cos) + (1 - a) * minmax(lex))
runs["rrf k=60, no-stop bm25"] = [rrf([lexns_r[i][:100], dense_r[i][:100]]) for i in range(len(qs))]

print("method                   top 1  top 5  top 10  (of 80)")
for name, r in runs.items():
    print(f"{name:<24}" + "".join(f"{sum(found(r, k)):>7}" for k in (1, 5, 10)))
h = found(runs["rrf k=60"])
print("\nrrf k=60 vs dense, top 5:", mcnemar(h, found(dense_r)))
print("rrf k=60 vs bm25, top 5: ", mcnemar(h, found(lex_r)))
print("rrf k=60 vs weighted a=0.5:", mcnemar(h, found(runs["weighted a=0.5"])))

    • Fusion beat both retrievers. RRF at k = 60 found 67 of 80 in the top 5. Against dense alone, 12 questions were found only by RRF and 2 only by dense (exact McNemar, p = 0.013); against BM25, 14 and 3 (p = 0.013). Of the retrieval changes measured on these pages, this is the first that clears a significance test.
    • k mattered little. Every k from 1 to 200 landed between 67 and 70 at top 5. k = 10 was best here, by three questions, which is too few to choose on.
    • Weighted fusion did just as well: 67 or 68 at top 5 for all three α, and a few more at top 1 (42 to 45 against 40). Min-max scaling behaved on this corpus; RRF still gets there with nothing to tune and no scores to rescale.
    • The better BM25 didn't carry through. Fusing dense with the stop-word-free BM25 from the BM25 page also gave 67 at top 5 (74 at top 10): once dense is in the mix, the stop words cost little.

    Limits: one document, one small embedding model, 80 single-fact questions drafted with an AI assistant. The k and α values were compared on the same questions they are reported on.

    Variations and parameters

    ChoiceWhat it changesDefault here
    RRF kSmall k rewards first places; large k flattens ranks so agreement between lists counts most.60
    Depth fusedHow far down each list RRF reads. A passage missing from a list gets nothing from it.Top 100 of each
    List weightsWeighted RRF multiplies each list's 1 / (k + r) by a weight, when one retriever is known to be better.Equal
    Score fusion αShare of the dense score after min-max scaling. Needs tuning; sensitive to outliers.0.3, 0.5, 0.7 tried
    More listsRRF takes any number: several query rewrites, a second embedding model, a title-only index.Two

    Pitfalls

    • Adding raw scores. BM25 scores here run into the tens and change scale with the query; cosine sits between about 0 and 1. Summing them lets BM25 decide alone. Rescale per query or fuse ranks (Cormack et al., 2009).
    • Fusing too shallow. If each list contributes only its top 5, a passage ranked 6th by both scores nothing. Fuse deeper than the k you finally keep (100 in the measurement).
    • Fusion can't add what neither list has. RRF reorders; it never finds a passage outside both lists. 68 questions had their passage in either top 5 (dense page); fusing the top 100 let k = 10 reach 70 by lifting passages both lists ranked just below 5th, but the 79 that were findable at all is the hard ceiling.
    • Tuning α or k on the questions you report. Any best setting chosen on the same 80 questions flatters itself by a question or two; k = 10's lead above is that size. Pick on separate questions, or keep the defaults; the evaluation page shows how wide the intervals are at 80 questions.

    In BrewSLM: retrieval is BM25, optionally reranked by a cross-encoder, rather than fused with dense vectors; the reranking page measures that approach on the same questions.

    Practice

    1. With k = 60, a passage is 1st in one list and absent from the other. Another is 5th in both. Which wins?

    The first scores 1/61 ≈ 0.0164. The second scores 2/65 ≈ 0.0308, so it wins: agreement beats one first place unless k is small.

    2. Why does min-max scaling make weighted fusion sensitive to outliers?

    The scale is set by the single highest and lowest score for that query. One unusually high BM25 score squeezes every other BM25 score towards 0, so the dense list decides the ranking for that query.

    3. You add a third list from a query rewrite and recall drops. What could cause it?

    With equal weights, a weak list gets the same vote as the good ones and pulls its wrong passages up. Check the third list's recall alone; weight it lower, or drop it. The query rewriting page shows a small model's rewrites can be worse than the original question.
