    Dense retrieval: search by embedding similarity

    Dense retrieval embeds every passage once with a sentence-embedding model, embeds the question with the same model, and returns the passages whose vectors are closest by cosine similarity. It matches meaning rather than shared words, so it finds "deductible" for "deduct", but it can miss exact identifiers such as form numbers that keyword search catches. On 80 questions about IRS Publication 17, all-MiniLM-L6-v2 found the answer passage in the top 5 for 57 and BM25 for 56, yet they missed different questions: 68 were found by at least one.

    Runs on: CPU, about a minute for every block on the page once the model is downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · faiss-cpu 1.9.0.post1 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    How dense retrieval works

    A sentence-embedding model turns any text into a fixed-length vector, 384 numbers for the model used here. It was trained so that a question and a passage that answers it end up pointing in similar directions. Retrieval is then three steps.

    1. Index once. Embed every chunk and keep the matrix: one row per chunk.
    2. Embed the question with the same model, at the same revision.
    3. Rank by similarity. With unit-length vectors, cosine similarity is a dot product, so scoring every chunk is one matrix multiply. For thousands of chunks that is instant; for millions, an approximate index such as FAISS HNSW trades a little recall for speed.

    This is called a bi-encoder: question and passage are embedded separately, which is what makes the index precomputable. A cross-encoder reads them together and is more accurate but has to run once per pair; that is the reranking page.

    The same three passages and question as the BM25 page, where "deduct" matched nothing. Install:

    import numpy as np
from sentence_transformers import SentenceTransformer

REV = "1110a243fdf4706b3f48f1d95db1a4f5529b4d41"     # pin the model revision
model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu", revision=REV)

docs = ["You can open a traditional IRA at any time.",
        "A Roth IRA contribution is not deductible.",
        "The standard deduction for a single filer."]
query = "Can I deduct a traditional IRA contribution?"
d = model.encode(docs, normalize_embeddings=True)
q = model.encode(query, normalize_embeddings=True)
print("passages:", d.shape, "| question:", q.shape, "| length:", round(float(np.linalg.norm(q)), 3))
for doc, score in zip(docs, d @ q):
    print(f"{score:.3f}  {doc}")

    Measured: dense against BM25 on IRS Publication 17

    Same corpus, chunks and 80 questions as the BM25 page: IRS Publication 17 (2025) cut into 512-character chunks with the chunking page's recursive splitter, 30 questions from that page plus 50 more drafted the same way and frozen before any retrieval ran. A chunk is relevant when it holds the question's whole evidence span.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    sha256: 2d2381d62c7c77ed | chunks: 2170 | questions: 80 | with a relevant chunk: 79
    import math, time
import faiss
from rank_bm25 import BM25Okapi

t0 = time.time()
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
print(f"index: {vecs.shape[0]} x {vecs.shape[1]} float32 = {vecs.nbytes / 1e6:.1f} MB, built in {time.time() - t0:.0f} s")
q_vecs = model.encode([q["question"] for q in qs], normalize_embeddings=True)
dense = np.argsort(-(q_vecs @ vecs.T), axis=1)

index = faiss.IndexFlatIP(vecs.shape[1])          # exact inner-product search
index.add(vecs)
_, top5 = index.search(q_vecs, 5)
print("FAISS flat top 5 equals numpy top 5:", bool((top5 == dense[:, :5]).all()))

words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
bm25 = BM25Okapi([words(c) for c in chunks])
lexical = np.array([np.argsort(-bm25.get_scores(words(q["question"]))) for q in qs])

def found(ranked, k):
    return [bool(set(ranked[i][:k]) & gold[i]) for i in range(len(qs))]

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c} questions only one found, exact McNemar p = {p:.3f}"

print("\n       top 1  top 5  top 10  top 20   (of 80)")
for name, ranked in (("bm25", lexical), ("dense", dense)):
    print(f"{name:<6}" + "".join(f"{sum(found(ranked, k)):>7}" for k in (1, 5, 10, 20)))
d5, b5 = found(dense, 5), found(lexical, 5)
print("found by either in the top 5:", sum(a or b for a, b in zip(d5, b5)))
print("dense vs bm25, top 5:", mcnemar(d5, b5))
print("\nonly dense found:")
for i in [i for i in range(len(qs)) if d5[i] and not b5[i]][:3]:
    print("  ", qs[i]["question"])
print("only bm25 found:")
for i in [i for i in range(len(qs)) if b5[i] and not d5[i]][:3]:
    print("  ", qs[i]["question"])

    • On totals, close. BM25 is three ahead at top 1, dense one ahead at top 5 and six ahead at top 10. At top 5 the paired test can't separate them (12 against 11 questions, p = 1.0).
    • Question by question, they differ a lot. 23 of 80 questions were found by only one of the two, and the union in the top 5 is 68, eleven above either alone. That disagreement is what hybrid search exploits.
    • The misses have a pattern. Of the 12 questions only dense found, many are worded unlike the publication: "babysitter" for child care, "shareholders' meeting" for stockholders' meetings, "let a friend talk to the IRS" for the third party designee. Most of the 11 only BM25 found share a rarer exact phrase with the passage: "trash pickup", "child support", "nondeductible IRA contributions", "savings bond".
    • FAISS's flat index returned exactly the numpy ranking. Flat search is exact; use it until the matrix no longer fits in memory or a query takes too long. Approximate indexes start paying off well past this page's 2,170 vectors.

    Limits: one small model (22 million parameters, trained on inputs of at most 128 tokens), one document and 80 single-fact questions drafted with an AI assistant. The embedding model comparison runs five other models on the same questions.

    Pitfalls

    • Long chunks lose their ends. all-MiniLM-L6-v2 truncates input over 256 word pieces (model card); at 512 characters, 89 Pub 17 chunks hit that limit, all on tax-table pages (chunking page).
    • Different model or revision on each side. Vectors from two models, or two revisions of one model, are not comparable, and nothing raises an error: scores just get worse. Pin the revision, as the code does, and store it next to the index (the revision argument).
    • Unnormalised vectors with a dot product. If the model doesn't normalise, a dot product favours long vectors over close ones. See cosine, dot and L2 for what that does to recall.
    • Exact tokens. Dense models blur identifiers such as "W-2c" or "Schedule LEP" into their neighbours; the questions only BM25 found above are the evidence. Keep a keyword retriever such as BM25 in the mix.

    In BrewSLM: document retrieval is BM25 plus a cross-encoder reranker, not dense vectors; all-MiniLM-L6-v2 embeddings are used for dataset diagnostics. Compare both on your data with the documents → Q&A sweep.

    Practice

    1. Why can a dense index be built once, while a cross-encoder can't be precomputed?

    A bi-encoder embeds the passage without seeing the question, so passage vectors don't depend on the query. A cross-encoder's score depends on the question and passage read together, so it has to run for every new question against every candidate.

    2. How much memory does a float32 index of one million 384-dimensional vectors take?

    1,000,000 × 384 × 4 bytes = 1.536 GB, before any index overhead. The 2,170 vectors above take 3.3 MB. Smaller vectors or int8 storage cut that; see dimensions vs quality.

    3. Dense finds 57 of 80 and BM25 56. Are they interchangeable?

    No. Equal totals can hide different misses. Look at the questions each one found alone (the discordant pairs); here the union was far above either total, which says to combine them rather than pick one.
