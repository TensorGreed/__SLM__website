    RAG evaluation: recall@k, MRR and nDCG

    Retrieval metrics score the ranked list a retriever returns against known relevant passages: recall@k asks whether the relevant passages made the top k, MRR rewards putting the first one high, and nDCG weighs every relevant passage by its rank and, if you have them, by graded labels. Each needs a set of questions with labelled answer passages, and the differences between retrievers need a paired test, because 80 questions is not many. On 80 questions about IRS Publication 17, reranking raised MRR@10 over hybrid search from 0.64 to 0.77 (paired bootstrap 95% interval for the gain: +0.06 to +0.21), while its gain in hit@5 had an interval that crossed zero.

    Runs on: CPU, about two minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    What each metric rewards

    All of these take one ranked list per question and the set of passages labelled relevant for it, then average over questions.

    • Hit rate@k: 1 if any relevant passage is in the top k, else 0. Most RAG write-ups call this recall@k, and the other RAG pages here report it.
    • Recall@k (strict): the share of the question's relevant passages found in the top k. It equals hit rate when each question has exactly one relevant passage.
    • Precision@k: the share of the top k that is relevant. With one relevant passage it can't exceed 1/k, so it says little for single-fact questions.
    • MRR@k (mean reciprocal rank): 1 / rank of the first relevant passage, 0 if none is in the top k. Rank 1 scores 1, rank 2 scores 0.5, rank 5 scores 0.2. It measures order.
    • nDCG@k: every relevant passage adds gain / log2(rank + 1), and the sum is divided by the best possible sum for that question. It is the one metric here that uses graded labels (somewhat relevant, highly relevant).

    For RAG, hit rate at the k you actually send matters most, because the generator only reads what it is given. MRR matters when you send few passages or when the model reads the first passage most closely.

    The metrics, from scratch, on one hand-checkable list

    No library: each metric is a couple of lines. The toy ranking has relevant passages at ranks 2 and 4, and passage d is graded more relevant than b. Install for the whole page:

    pip install torch==2.5.1 --index-url https://download.pytorch.org/whl/cpu
pip install sentence-transformers==3.3.1 transformers==4.46.3 tokenizers==0.20.3 \
    huggingface_hub==0.36.2 rank-bm25==0.2.2 pypdf==5.1.0 numpy==2.1.3
    import math

def hit_rate(ranked, relevant, k):
    return float(bool(set(ranked[:k]) & relevant))

def recall(ranked, relevant, k):
    return len(set(ranked[:k]) & relevant) / len(relevant)

def precision(ranked, relevant, k):
    return len(set(ranked[:k]) & relevant) / k

def rr(ranked, relevant, k=10):
    return next((1 / r for r, d in enumerate(ranked[:k], 1) if d in relevant), 0.0)

def ndcg(ranked, grades, k=10):
    """grades: {passage: gain}; a passage not in grades has gain 0."""
    dcg = sum((2 ** grades.get(d, 0) - 1) / math.log2(r + 1) for r, d in enumerate(ranked[:k], 1))
    ideal = sum((2 ** g - 1) / math.log2(r + 1) for r, g in enumerate(sorted(grades.values(), reverse=True)[:k], 1))
    return dcg / ideal if ideal else 0.0

ranked = ["a", "b", "c", "d", "e"]
grades = {"b": 1, "d": 2}
rel = set(grades)
print("hit@1", hit_rate(ranked, rel, 1), "| hit@3", hit_rate(ranked, rel, 3), "| recall@3", recall(ranked, rel, 3),
      "| precision@3", round(precision(ranked, rel, 3), 3))
print("RR", rr(ranked, rel), "| nDCG@5", round(ndcg(ranked, grades, 5), 3),
      "| nDCG@5 with d and b swapped", round(ndcg(["a", "d", "c", "b", "e"], grades, 5), 3))

    Output

    hit@1 0.0 | hit@3 1.0 | recall@3 0.5 | precision@3 0.333
RR 0.5 | nDCG@5 0.53 | nDCG@5 with d and b swapped 0.64

    By hand: the first relevant passage is at rank 2, so RR = 0.5. DCG = (2¹ − 1)/log2 3 + (2² − 1)/log2 5 = 0.631 + 1.292 = 1.923; the ideal order (d, then b) gives 3 + 0.631 = 3.631, so nDCG = 0.530. Swapping d and b changes nothing for RR, hit rate or recall, but nDCG rises because the more relevant passage moved up.

    Measured: four retrievers, five metrics, on IRS Publication 17

    The corpus, 512-character chunks and 80 frozen questions are the ones every RAG page here uses (30 + 50). Relevance gets two grades this time: 2 for a chunk holding the whole evidence span (what the other pages count), 1 for a chunk holding only part of it.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Output

    sha256: 2d2381d62c7c77ed | chunks: 2170 | questions: 80 | with a relevant chunk: 79

    Setup. The four retrievers from the BM25, dense, hybrid and reranking pages, rebuilt here so the block stands alone. The last lines give a paired bootstrap interval: resample the 80 questions with replacement 10,000 times and take the 2.5th and 97.5th percentiles of the mean per-question difference.

    import numpy as np
from sentence_transformers import SentenceTransformer, CrossEncoder
from rank_bm25 import BM25Okapi

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
dense = np.argsort(-(model.encode([q["question"] for q in qs], normalize_embeddings=True) @ vecs.T), axis=1)
words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
bm25 = BM25Okapi([words(c) for c in chunks])
lexical = np.array([np.argsort(-bm25.get_scores(words(q["question"]))) for q in qs])

def rrf(rankings, k=60):
    score = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=lambda d: -score[d])

hybrid = [rrf([lexical[i][:100], dense[i][:100]]) for i in range(len(qs))]
ce = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2", device="cpu", revision="233902d25c440f23af6f7d6e94d2946bac0bee0a")
reranked = []
for i, q in enumerate(qs):
    pool = hybrid[i][:30]
    scores = ce.predict([(q["question"], chunks[j]) for j in pool], batch_size=32)
    reranked.append([pool[j] for j in np.argsort(-scores)])

grades = []                                  # 2 = whole evidence span in the chunk, 1 = part of it
for q, g in zip(qs, gold):
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    part = {j for j, s in enumerate(starts) for a, b in occ if s < b and a < s + len(chunks[j])}
    grades.append({**{j: 1 for j in part}, **{j: 2 for j in g}})

runs = {"bm25": lexical, "dense": dense, "hybrid (rrf)": hybrid, "hybrid + rerank": reranked}
per_q = {}
print("retriever         hit@1  hit@5  recall@5  prec@5  MRR@10  nDCG@10")
for name, r in runs.items():
    r = [list(x[:10]) for x in r]
    rows = [(hit_rate(r[i], gold[i], 1), hit_rate(r[i], gold[i], 5), recall(r[i], gold[i], 5) if gold[i] else 0.0,
             precision(r[i], gold[i], 5), rr(r[i], gold[i]), ndcg(r[i], grades[i])) for i in range(len(qs))]
    per_q[name] = np.array(rows)
    print(f"{name:<16}" + "".join(f"{v:>8.3f}" for v in per_q[name].mean(axis=0)))

rng = np.random.default_rng(0)
for a, b, col, label in (("hybrid + rerank", "hybrid (rrf)", 4, "MRR@10"), ("hybrid + rerank", "hybrid (rrf)", 1, "hit@5"),
                         ("dense", "bm25", 4, "MRR@10")):
    diff = per_q[a][:, col] - per_q[b][:, col]
    boots = [diff[rng.integers(0, len(diff), len(diff))].mean() for _ in range(10_000)]
    lo, hi = np.percentile(boots, [2.5, 97.5])
    print(f"{a} minus {b}, {label}: {diff.mean():+.3f}, 95% CI {lo:+.3f} to {hi:+.3f}")

    retriever         hit@1  hit@5  recall@5  prec@5  MRR@10  nDCG@10
bm25               0.487   0.700   0.688   0.142   0.593   0.637
dense              0.450   0.713   0.713   0.145   0.574   0.645
hybrid (rrf)       0.500   0.838   0.821   0.172   0.637   0.705
hybrid + rerank    0.675   0.900   0.885   0.185   0.768   0.816
hybrid + rerank minus hybrid (rrf), MRR@10: +0.131, 95% CI +0.060 to +0.205
hybrid + rerank minus hybrid (rrf), hit@5: +0.062, 95% CI -0.013 to +0.138
dense minus bm25, MRR@10: -0.019, 95% CI -0.120 to +0.083
    • The metrics agree on the winner and disagree on the size of the win. Every column ranks reranking first. But from hybrid to reranked, hit@5 moves by 6 points, MRR by 13 and hit@1 by 18: the reranker's work is mostly order, and only the order-aware metrics see it in full.
    • Precision@5 is close to useless here. With about one relevant chunk per question it is capped near 0.2 and simply tracks hit@5 divided by five.
    • Recall@5 and hit@5 are nearly identical because only a few questions (q15, q45, q56 and q57, whose spans occur more than once) have more than one relevant chunk; on a corpus with many relevant passages per question they diverge.
    • The intervals say what to trust. The reranker's MRR gain has an interval of +0.06 to +0.21, clear of zero; its hit@5 gain runs from −0.01 to +0.14, so on hit@5 alone you couldn't claim it. Dense against BM25 on MRR runs from −0.12 to +0.08, which matches the tie on the dense page.

    Limits: the labels come from one evidence span per question, so a chunk that answers the question in other words counts as irrelevant. That makes every number here a lower bound, and it penalises all retrievers alike. 80 single-fact questions drafted with an AI assistant, one document.

    Variations and parameters

    ChoiceWhat it changesDefault here
    kMatch the k you send to the generator for hit rate; MRR and nDCG are usually cut at 10.5 and 10
    Relevance labelsBinary (holds the answer or not) or graded. Graded labels only change nDCG.Evidence span: 2 whole, 1 partial
    Gain function2^g − 1 stresses highly relevant passages; plain g is linear. Report which you used.2^g − 1
    Questions with no relevant passageCount them as 0 (honest about the ceiling) or drop them (flatters every system).Counted, as 0
    UncertaintyPaired bootstrap on per-question differences, or McNemar on hit/miss pairs.Bootstrap, 10,000 resamples

    Pitfalls

    • Labels that only know one passage. Labelling relevance by one evidence span undercounts every retriever when the corpus repeats a fact; the TREC pooling approach labels the union of several systems' top results for this reason.
    • Unpaired comparisons. Two retrievers scored on the same questions should be compared question by question. Here dense and BM25 differ by 0.01 in hit@5 while 23 questions flip (dense page); unpaired averages hide that.
    • Good retrieval, wrong answer. Retrieval metrics stop at the passages. In BrewSLM's Pub 17 run the right passage was retrieved for 37 of 41 questions, yet 5 answers were still wrong because the model misread it (IRS Pub 17 post). Score answers too, and check faithfulness.
    • Tuning on the test questions. A retrieval setting picked as the best of nine on 41 questions flatters itself by a few rows, as the IRS Pub 17 post says of its own sweep. Keep some questions back.

    In BrewSLM: the documents → Q&A check records whether the right passage was retrieved next to the judged answer, so you can split wrong answers into retrieval misses and reading errors.

    Practice

    1. Three questions: relevant passage at ranks 1, 3 and not in the top 10. What is MRR@10?

    (1 + 1/3 + 0) / 3 = 0.444.

    2. Retriever A has higher hit@5, B has higher MRR@10. You send 5 passages to a model that reads all of them. Which do you pick?

    Probably A: what matters is whether the passage is in what the model reads. MRR rewards order inside the list, which helps when you send only one or two passages, or when the model favours the first one. Check with answer-level scores before deciding.

    3. A bootstrap 95% interval for a difference in hit@5 is −0.01 to +0.09. What do you report?

    That the difference is not distinguishable from zero on these questions; the point estimate leans positive. "Suggestive" at most. More questions would narrow the interval.
