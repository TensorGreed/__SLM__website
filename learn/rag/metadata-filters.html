    Metadata filters in RAG: pre-filtering, post-filtering and routing

    A metadata filter restricts retrieval to chunks whose tags match a condition, such as a chapter, product, date or access level, either before the similarity search (pre-filtering) or by dropping non-matching hits after it (post-filtering). Pre-filtering always returns k results from the allowed set; post-filtering can return fewer, and a filter only helps if you know the right value for the question. On 80 questions about IRS Publication 17, filtering to the correct chapter raised dense top-5 recall from 57 to 68 with no question lost, but both routers that guessed the chapter from the question did worse than no filter at all.

    Runs on: CPU, about a minute for every block on the page once the model is downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    Filters narrow the search, if you know the value

    Every chunk can carry fields besides its text: source document, section, date, language, product, the user groups allowed to see it. A filter uses them to shrink the candidate set. There are two places to apply it:

    • Pre-filtering: search only among chunks that match. You always get k results, all allowed. With an exact search this is just indexing a subset; approximate indexes need filter support built in.
    • Post-filtering: search everything, then drop the hits that don't match. Simple to bolt on, but if most of the top k fail the filter, you return fewer than k, sometimes none.

    Some filters are hard requirements, such as permissions or "only the 2025 edition", and are never optional. Others are relevance hints, such as "this is probably a question about IRAs", and those only help when the value is right. For those you need a router: something that picks the value from the question.

    Chapter tags from the page footers

    Publication 17 prints a running footer on every page, "28 Chapter 3 Dependents Publication 17 (2025)", which the cleaning step leaves in. That gives every page a chapter for free. Pages without one (the front matter, tax tables, taxpayer rights and index) get a label of their own. Install:

    The corpus, 512-character chunks and 80 frozen questions shared by every RAG page here (30 + 50):

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    from collections import Counter

pages = text.split("\n\n")
FOOTER = re.compile(r"Chapter (\d+) ([A-Z][A-Za-z ,'’()-]+?) (?:Page \d+ )?(?=Publication 17 \(2025\)|\d+ *$)|"
                    r"Publication 17 \(2025\) Chapter (\d+) ([A-Z][A-Za-z ,'’()-]+?) (?=Page \d+|\d+ *$)")
def page_chapter(n, page):
    m = FOOTER.search(page)
    if m:
        num, title = (m.group(1), m.group(2)) if m.group(1) else (m.group(3), m.group(4))
        return f"{int(num)} {title.strip()}"
    return ("front matter" if n < 8 else "tax tables" if n <= 127 else "rights and help" if n <= 131
            else "index" if n <= 141 else "where to file")

page_tag = [page_chapter(n, p) for n, p in enumerate(pages, 1)]
chunk_page = [text.count("\n\n", 0, s) for s in starts]          # 0-based page each chunk starts on
chunk_tag = [page_tag[p] for p in chunk_page]
q_tag = [page_tag[q["page"] - 1] for q in qs]                  # the chapter of the evidence page
tags = sorted(set(page_tag), key=lambda t: (not t[0].isdigit(), int(t.split()[0]) if t[0].isdigit() else 0, t))
print(len(tags), "tags:", tags[:3], "...", tags[-3:])
print("chunks per tag (largest 3):", Counter(chunk_tag).most_common(3))
print("questions per tag (largest 3):", Counter(q_tag).most_common(3))

    A chunk takes the tag of the page it starts on, so a chunk that runs across a chapter break carries one tag. The questions get the tag of the page their evidence is on; that is the "oracle" filter, the best a perfect router could do.

    Measured: no filter, oracle filter, a router, and post-filtering

    Setup. Dense retrieval with all-MiniLM-L6-v2 at a pinned revision, top 5. The router embeds a label for each tag ("Chapter 9: Individual Retirement Arrangements (IRAs)") and picks the one closest to the question; a second router takes the most common tag among the top 10 unfiltered hits. Post-filtering searches everything, keeps the top 5, then drops hits whose tag doesn't match the oracle value.

    import math
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
q_vecs = model.encode([q["question"] for q in qs], normalize_embeddings=True)
sims = q_vecs @ vecs.T
ranked = np.argsort(-sims, axis=1)
tag_arr = np.array(chunk_tag)

def search(i, allowed=None, k=5):
    if allowed is None:
        return list(ranked[i][:k])
    return [j for j in ranked[i] if tag_arr[j] == allowed][:k]        # pre-filter: k from the allowed set

def label(t):
    return f"Chapter {t.split(' ', 1)[0]}: {t.split(' ', 1)[1]}" if t[0].isdigit() else f"IRS Publication 17 {t}"
tag_vecs = model.encode([label(t) for t in tags], normalize_embeddings=True)
route_by_label = [tags[int(np.argmax(tag_vecs @ v))] for v in q_vecs]
route_by_hits = [Counter(chunk_tag[j] for j in ranked[i][:10]).most_common(1)[0][0] for i in range(len(qs))]

found = lambda results: [bool(set(r) & gold[i]) for i, r in enumerate(results)]
arms = {"no filter": [search(i) for i in range(len(qs))],
        "pre-filter, oracle chapter": [search(i, q_tag[i]) for i in range(len(qs))],
        "pre-filter, router: tag labels": [search(i, route_by_label[i]) for i in range(len(qs))],
        "pre-filter, router: top-10 vote": [search(i, route_by_hits[i]) for i in range(len(qs))],
        "post-filter, oracle chapter": [[j for j in search(i) if chunk_tag[j] == q_tag[i]] for i in range(len(qs))]}

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.3f}"

print("arm                              found  results returned (mean, min)")
for name, res in arms.items():
    print(f"{name:<32} {sum(found(res)):>3}/80   {np.mean([len(r) for r in res]):.2f}, {min(len(r) for r in res)}")
print("\nrouter accuracy: tag labels", sum(a == b for a, b in zip(route_by_label, q_tag)), "of 80 | top-10 vote",
      sum(a == b for a, b in zip(route_by_hits, q_tag)), "of 80")
base = found(arms["no filter"])
for name in ("pre-filter, oracle chapter", "pre-filter, router: top-10 vote"):
    print(f"{name} vs no filter: {mcnemar(found(arms[name]), base)}")

no filter                         57/80   5.00, 5
pre-filter, oracle chapter        68/80   5.00, 5
pre-filter, router: tag labels    26/80   5.00, 5
pre-filter, router: top-10 vote   52/80   5.00, 5
post-filter, oracle chapter       57/80   3.33, 0

router accuracy: tag labels 28 of 80 | top-10 vote 64 of 80
pre-filter, oracle chapter vs no filter: 11 vs 0, p = 0.001
pre-filter, router: top-10 vote vs no filter: 6 vs 11, p = 0.332
    • The right filter helps. Restricting the search to the evidence's chapter raised top-5 recall from 57 to 68: eleven questions gained and none lost (exact McNemar, p = 0.001). Out-of-chapter chunks that happened to share the wording were no longer competing.
    • A router that guesses is the hard part. Matching the question to chapter titles picked the right chapter for only 28 of 80 questions, and a wrong pre-filter makes the answer unreachable: recall fell to 26. Voting among the top 10 unfiltered hits routed 64 of 80 correctly and still ended below no filter (52 against 57; 6 gained, 11 lost).
    • Post-filtering never adds a hit, and returns fewer results. It can only remove passages from the unfiltered top 5. Recall stayed at 57, while the number of results fell to 3.3 on average, and to none for some questions.

    Limits: the oracle chapter comes from where the evidence is, which a real system doesn't know; it is an upper bound. Chapters are big (some hold hundreds of chunks), so the filter is coarse. One document, one small model, 80 questions drafted with an AI assistant.

    Where the value comes fromThe user (a dropdown), the application (permissions, date), or a router guessing from the question.Oracle and two routers

    Pitfalls

    • Post-filtering a small top k. Filtering the top 5 left some questions with no result (table above). Over-fetch, or pre-filter. Vector databases document the same trade-off for approximate indexes; FAISS, for example, takes an ID selector in its per-query search parameters so the filter runs inside the search.
    • Treating a guessed filter as a hard filter. A wrong router value makes the right passage unreachable. Use guessed values as a boost, or fall back to unfiltered search when the filtered scores are low; the router rows above show the cost.
    • Metadata that drifts from the text. Tags derived once and never rebuilt go stale when the document changes. Here they come from footers in the same text (code above), so they are rebuilt with the index.
    • Filtering instead of fixing retrieval. On these questions reranking reached 72 of 80 at top 5 with no metadata at all, more than the oracle chapter filter on dense retrieval.

    In BrewSLM: retrieval searches the whole project corpus with no metadata filter; passages keep their source document, which a filter could use. See documents → Q&A.

    Practice

    1. A user may only see documents from their department. Pre-filter or post-filter?

    Pre-filter. It is a hard requirement, and post-filtering could return an empty list when the top hits belong to other departments, or tempt someone to over-fetch and leak scores. Search only the allowed set.

    2. Your router picks the right chapter 80% of the time. When does a hard filter still help?

    When the gain on the 80% outweighs the loss on the 20%, which are made unanswerable. Above, 64 of 80 correct (80%) still lost to no filter. Measure both arms on labelled questions; a soft boost, or a fallback to unfiltered search, is usually safer than a hard filter at that accuracy.

    3. Post-filtering returns 3.3 results on average from a top 5, and none for some questions. What would you change?

    Over-fetch before filtering (retrieve 25 or 50, filter, then keep 5), or move the filter before the search.
