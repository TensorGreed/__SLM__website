    Query rewriting for RAG: does it help retrieval?

    Query rewriting asks a language model to turn the user's question into a better search query before retrieval: a keyword version, a clearer paraphrase, or several variants whose results are fused. It can fix vague or conversational questions, but a rewrite can also drop the one word that mattered. On 80 questions about IRS Publication 17, a 1.5B model's keyword rewrites lowered top-5 recall for both BM25 and dense retrieval, while appending the rewrite to the original question raised them a little (BM25 56 to 59, dense 57 to 61), gains too small to separate from noise.

    Runs on: CPU, about five minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · Ollama 0.32.9 · qwen2.5:1.5b-instruct (Q4_K_M) · CPU (20-core Arm, no GPU)

    Three kinds of rewrite

    People ask questions the way they talk ("My refund hasn't shown up yet. Can I send in a second original return?"), and documents are written the way institutions write ("Don't file more than one original return for the same year"). Rewriting tries to close that gap before the retriever runs.

    • Keyword rewrite. Strip the conversational parts and keep the terms a document would use. Aimed at keyword retrievers such as BM25, which score question words like "can" and "my" too.
    • Expansion. Keep the original and append the rewrite, so nothing from the question is lost and new terms are added.
    • Multi-query. Generate several different queries, retrieve for each, and fuse the lists with reciprocal rank fusion. More chances to hit the passage, and more chances to pull in noise.

    In chat systems a fourth kind matters most: turning a follow-up such as "and what if I'm over 50?" into a standalone question using the conversation so far. The questions here are all standalone, so this page doesn't measure that.

    def keyword_query(question):
    out = chat("Rewrite this question as a short search query for a tax guide: the key terms only, "
               f"no question words. Reply with the query and nothing else.\n\nQuestion: {question}", num_predict=40)
    return out.replace('"', "").strip()

def multi_queries(question, n=3):
    out = chat(f"Write {n} different search queries that would find the answer to this question in a tax guide. "
               f"One per line, no numbering, nothing else.\n\nQuestion: {question}", num_predict=90)
    return [l.strip(' -*0123456789."') for l in out.split("\n") if l.strip()][:n]

    Measured: rewrites against the original question on IRS Publication 17

    Same corpus, 512-character chunks and 80 frozen questions as the other RAG pages (30 + 50); a chunk is relevant when it holds the whole evidence span, and 79 is the ceiling.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    import math, time
import numpy as np
from sentence_transformers import SentenceTransformer
from rank_bm25 import BM25Okapi

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
bm25 = BM25Okapi([words(c) for c in chunks])
dense_rank = lambda texts: np.argsort(-(model.encode(texts, normalize_embeddings=True) @ vecs.T), axis=1)
bm25_rank = lambda texts: [np.argsort(-bm25.get_scores(words(t))) for t in texts]

def rrf(rankings, k=60):
    score = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=lambda d: -score[d])

def found(ranked, k=5):
    return [bool(set(list(ranked[i])[:k]) & gold[i]) for i in range(len(qs))]

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.3f}"

t0 = time.time()
questions = [q["question"] for q in qs]
keyword = [keyword_query(q) for q in questions]
multi = [multi_queries(q) for q in questions]
print(f"rewrites: {(time.time() - t0) / len(qs):.1f} s a question for both kinds")

runs = {}
for name, rank in (("bm25", bm25_rank), ("dense", dense_rank)):
    runs[name, "original"] = rank(questions)
    runs[name, "keyword rewrite"] = rank(keyword)
    runs[name, "original + rewrite"] = rank([q + " " + k for q, k in zip(questions, keyword)])
    runs[name, "multi-query (RRF)"] = [rrf([r[:50] for r in rank([q] + m)]) for q, m in zip(questions, multi)]
print("\nquery                    bm25 top 5   dense top 5   (of 80)")
for arm in ("original", "keyword rewrite", "original + rewrite", "multi-query (RRF)"):
    print(f"{arm:<24} {sum(found(runs['bm25', arm])):>8}    {sum(found(runs['dense', arm])):>10}")
for name in ("bm25", "dense"):
    for arm in ("keyword rewrite", "original + rewrite", "multi-query (RRF)"):
        print(f"{name}, {arm} vs original: {mcnemar(found(runs[name, arm]), found(runs[name, 'original']))}")
lost = [i for i, (a, b) in enumerate(zip(found(runs["bm25", "keyword rewrite"]), found(runs["bm25", "original"]))) if b and not a]
print("\nlost by the keyword rewrite (bm25):", questions[lost[0]], "->", repr(keyword[lost[0]]))

lost by the keyword rewrite (bm25): Does a direct transfer between IRA trustees trigger the one-rollover-per-year rule? -> 'Does transferring funds from an IRA trustee violate the one-rollover-per-year rule?'
    • Replacing the question hurt. The keyword rewrite lost questions for both retrievers: BM25 fell from 56 to 49 (7 gained, 14 lost) and dense from 57 to 54. The paired tests can't call the losses significant (p = 0.19 and 0.63), but no arm that replaced the question beat the original.
    • Appending helped a little. Original plus rewrite reached 59 for BM25 and 61 for dense, three and four questions up, with p = 0.58 and 0.34: suggestive at best. Keeping the original protects against a rewrite that drops the key term.
    • Multi-query fusion did worse for dense retrieval: 49 against 57 (5 gained, 13 lost, p = 0.096). Three rewrites plus the original, fused with RRF, gave each weak query the same vote as the real one. For BM25 it was a wash (55 against 56).

    Limits: this is a 1.5B model, the size the rest of these pages use, and at this size the rewrites are the weak link; a larger model that knows tax vocabulary may well turn these results round. One prompt per kind, not tuned. 80 single-fact standalone questions drafted with an AI assistant; conversational follow-ups, where rewriting is most useful, aren't tested.

    Pitfalls

    • Rewrites drop the decisive word. The lost example above is typical: the rewrite is fluent and loses the term the passage uses. Measure against the original question before switching (table above).
    • Instructions not followed. Small models add labels, quotes or numbering despite being told not to, and can change the question's meaning: in the example above, "let a friend talk to the IRS about my return" became helping a friend with their return. Clean the output and read a sample.
    • One more model call per question. Here the two kinds of rewrite took about 5.6 seconds a question on CPU. Multi-query also multiplies retrieval calls. The rewrite-retrieve-read paper (Ma et al., 2023) trains a small rewriter for this reason.
    • Equal-weight fusion of weak lists. RRF trusts every list the same. See the hybrid search page on adding a weak list.

    In BrewSLM: retrieval uses the question as asked, with no rewriting step; the documents → Q&A sweep tunes passage count, reranker and passage size instead.

    Practice

    1. Why can appending a rewrite help BM25 while replacing the question hurts it?

    Appending only adds terms: the original words that matched the passage still score, and any new term the passage uses adds more. Replacing removes the original terms, so if the rewrite loses the one rare word that matched, the passage drops out.

    2. When is query rewriting most likely to pay off?

    In conversations, where a follow-up ("what about for 2024?") is meaningless without earlier turns; for very short or vague queries; and when the rewriter knows the corpus's vocabulary. For clear standalone questions, measure first.

    3. Your multi-query setup raises recall@20 but lowers recall@5. What is happening?

    More lists put more distinct passages into the pool, so the right one is more often somewhere in it, but the extra lists also push other passages into the top 5. A reranker over the larger pool can recover the order.
