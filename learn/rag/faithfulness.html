    Faithfulness: is the answer supported by the passages?

    A RAG answer is faithful when everything it states is supported by the passages it was given; it can be faithful and still wrong if the passages were wrong, and correct but unfaithful if it came from the model's memory. Automatic checks use a natural-language-inference (NLI) model or an LLM judge to ask whether each claim follows from the passages, and they need testing before their scores mean anything. On 23 sentences taken from IRS Publication 17, two small NLI models called only 8 and 13 of the true sentences supported, while a 1.5B LLM judge accepted all 23 true ones and 3 of the 23 copies with one number changed.

    Faithful is not the same as correct

    Two questions get mixed up when people evaluate RAG answers:

    • Correctness: does the answer match the truth (an answer key)?
    • Faithfulness (also called groundedness): is every claim in the answer supported by the passages the model was given?

    They come apart in both directions. If retrieval returned last year's figure, a faithful answer is wrong. If the model ignored the passages and answered from memory, a correct answer is unfaithful, and the next one from memory may not be correct. Faithfulness is what lets a user trust the citation, and it needs no answer key, so it can be checked on live traffic.

    The usual automatic check splits the answer into claims and asks, for each, whether the passages entail it. Two kinds of checker:

    • NLI cross-encoders classify a (premise, hypothesis) pair as entailment, neutral or contradiction. Small, fast, deterministic.
    • LLM judges are prompted with the passage and the claim and asked "supported, yes or no?". Flexible, and only as reliable as the judge model.

    req = urllib.request.Request(OLLAMA + "/api/chat", json.dumps(body).encode(), {"Content-Type": "application/json"})
    return json.load(urllib.request.urlopen(req, timeout=900))["message"]["content"].strip()

    import numpy as np
from sentence_transformers import CrossEncoder

nli = {"deberta-v3-xsmall": CrossEncoder("cross-encoder/nli-deberta-v3-xsmall", device="cpu",
                                         revision="a150876415327c80daeff35ca6f68f5ed8cf5c24"),
       "MiniLM2-L6": CrossEncoder("cross-encoder/nli-MiniLM2-L6-H768", device="cpu",
                                  revision="b95119ce93d3e065de6214e38cd4a97b0f2f2c6d")}

def nli_supported(model, premise, claim):
    label = model.model.config.id2label[int(np.argmax(model.predict([(premise, claim)])[0]))]
    return label == "entailment"

def judge_supported(premise, claim):
    out = chat(f"Passage:\n{premise}\n\nClaim: {claim}\n\n"
               "Is the claim fully supported by the passage? Answer yes or no.", num_predict=3)
    return out.strip().lower().startswith("yes")

premise = ("Limit on exclusion. You can generally exclude from gross income up to $420 a day for 2025. "
           "See Limit on exclusion in Pub. 525 for more information.")
for claim in ("You can exclude up to $420 a day for 2025.",
              "You can exclude up to $520 a day for 2025.",
              "Workers' compensation is fully exempt from tax."):
    verdicts = {name: nli_supported(m, premise, claim) for name, m in nli.items()}
    print(f"{claim:<50} {verdicts}  judge: {judge_supported(premise, claim)}")

    Measured: changed numbers, wrong passages and real answers

    The corpus and questions are the ones every RAG page here uses: IRS Publication 17 (2025) in 512-character chunks and 80 frozen questions, of which 47 have a short answer key (pub17-answer-keys.json).

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Controlled test. For every keyed question whose key contains a number (a dollar amount, a form, a count of days), the claim is the sentence of the passage that holds the evidence span. Each claim is checked three ways: against its own passage (should be supported), with the key's number changed by one digit (should not), and against another question's passage (should not). These labels are known by construction, so no judgement is needed.

    Real answers. Then the model answers the 47 keyed questions from the top 5 chunks of an embedding search, as on the what is RAG page, and the better NLI model checks each answer against each passage. The answer counts as supported if any one passage entails it.

    import time
from collections import Counter
from sentence_transformers import SentenceTransformer

keys = json.load(open("pub17-answer-keys.json"))["keys"]
flat = lambda s: " ".join(s.split())

def claim_sentence(q):
    a = text.index(q["evidence"])
    start = max(text.rfind(". ", 0, a) + 2, a - 300)
    end = text.find(". ", a + len(q["evidence"]))
    return flat(text[start:end + 1 if end != -1 else None])

def change_number(sentence, key):
    m = re.search(r"\d[\d,]*", key)
    if not m or m.group(0) not in sentence:
        return None
    old = m.group(0)
    return sentence.replace(old, str(int(old[0]) % 9 + 1) + old[1:], 1)    # 4 -> 5, 9 -> 1

cases = []
numeric = [(i, q) for i, q in enumerate(qs) if q["id"] in keys and gold[i]
           and any(re.search(r"\d", k) for k in keys[q["id"]])]
for n, (i, q) in enumerate(numeric):
    claim = claim_sentence(q)
    changed = next((c for k in keys[q["id"]] if (c := change_number(claim, k))), None)
    if changed is None:
        continue
    own = flat(chunks[min(gold[i])])
    other = flat(chunks[min(gold[numeric[(n + 1) % len(numeric)][0]])])
    cases += [("own passage", own, claim), ("number changed", own, changed), ("other passage", other, claim)]

t0 = time.time()
table = {}
for cond, premise, claim in cases:
    row = table.setdefault(cond, Counter())
    row["n"] += 1
    for name, m in nli.items():
        row[name] += nli_supported(m, premise, claim)
    row["qwen 1.5B judge"] += judge_supported(premise, claim)
print(f"{len(cases) // 3} claims, {len(cases)} checks, {time.time() - t0:.0f} s")
print("\njudged supported      deberta-v3-xsmall  MiniLM2-L6  qwen 1.5B judge   (should be)")
for cond, should in (("own passage", "all"), ("number changed", "none"), ("other passage", "none")):
    r = table[cond]
    print(f"{cond:<20} " + "".join(f"{r[k]:>8}/{r['n']:<6}" for k in ("deberta-v3-xsmall", "MiniLM2-L6", "qwen 1.5B judge"))
          + f"   {should}")

embedder = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                               revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
index = embedder.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
norm = lambda s: re.sub(r"[^a-z0-9]", "", s.lower())
cross = Counter()
for i, q in enumerate(qs):
    if q["id"] not in keys:
        continue
    ids = list(np.argsort(-(index @ embedder.encode(q["question"], normalize_embeddings=True)))[:5])
    passages = "\n\n".join(f"[{n}] {flat(chunks[j])}" for n, j in enumerate(ids, 1))
    answer = chat("Answer the question using only the passages below, in one or two sentences. "
                  f"If they don't contain the answer, say so.\n\n{passages}\n\nQuestion: {q['question']}")
    supported = any(nli_supported(nli["MiniLM2-L6"], flat(chunks[j]), answer) for j in ids)
    right = any(norm(k) in norm(answer) for k in keys[q["id"]])
    cross["right" if right else "wrong", "supported" if supported else "not supported"] += 1
print("\nreal answers (47), key match x MiniLM2 NLI:")
for r in ("right", "wrong"):
    print(f"  {r:<6} supported {cross[r, 'supported']:>2}   not supported {cross[r, 'not supported']:>2}")

  right  supported 20   not supported 10

    • The NLI models were too strict on true claims. Each claim is a sentence copied from its own passage, so all 23 should be supported; deberta-v3-xsmall said so for 8 and MiniLM2 for 13. This page did not dig into why; a likely reason is that a 512-character chunk cuts the context a sentence relies on (a list or table heading), and small NLI models then answer "neutral".
    • Changed numbers still got through. With one digit changed, the NLI models accepted 4 and 5 of 23, the judge 3. The toy shows the pattern: deberta accepted $520 a day as readily as $420.
    • The 1.5B judge did best here, accepting all 23 true claims and 3 changed ones, at the cost of a model call per check (the 69 checks took minutes, not milliseconds). It also accepted 4 claims against an unrelated passage, which neither NLI model did. No checker was reliable on all three rows.
    • On real answers, "supported" and "right" are different axes. MiniLM2 called 11 wrong answers supported and 10 right answers unsupported, out of 47. Whole answers often combine two passages or paraphrase, which a single-passage NLI check reads as unsupported.

    Limits: the controlled claims change only numbers, and only for the questions whose keys hold one; the real-answer check uses whole answers as one claim, where splitting into sentences would be fairer to the NLI models. NLI models read at most 512 tokens, so each passage is checked separately. All checkers here are small; larger judges are generally better, and still need this kind of test before you trust their scores.

    Variations and parameters

    ChoiceWhat it changesDefault here
    Claim unitWhole answer, sentence, or atomic facts extracted by a model. Smaller units are fairer and cost more checks.Sentence (controlled), whole answer (real)
    PremiseOne passage at a time, or all passages joined (exceeds small NLI models' 512 tokens).One at a time, any-of
    Decision ruleArgmax label, or entailment probability above a threshold tuned on labelled pairs.Argmax
    CheckerNLI cross-encoder, LLM judge, or exact-quote checks (see citations).Two NLI models, one 1.5B judge
    Test set for the checkerPerturbed claims (changed numbers, negations, swapped entities) with known labels.Changed numbers, other passage

    Pitfalls

    • Trusting a checker you haven't tested. The changed-number row above is the test to run on any faithfulness metric before using it. Benchmarks such as FRANK (Pagnoni et al., 2021) found that factuality metrics miss many error types.
    • Calling faithfulness correctness. A faithful answer built on a wrong passage is wrong. In BrewSLM's Pub 17 run, the standard-deduction answer quoted a worked example faithfully and gave the wrong figure (IRS Pub 17 post, "five questions of our own").
    • Input limits. NLI cross-encoders read about 512 tokens; joined passages are truncated without warning. Check each passage, or use a long-input model (nli-deberta-v3-xsmall model card).
    • Judging with the generator. Using the same small model to answer and to judge shares its blind spots. Use a different, ideally stronger, judge, and calibrate it against human labels on a sample, as BrewSLM's judge calibration does: you label a sample blind and it reports agreement and kappa (scoring modes).

    In BrewSLM: answers are graded by a judge model against an answer key, and a second judge prompt records whether the right passage was retrieved; the documents → Q&A page describes both.

    Practice

    1. The passage says $420; the answer says $420 and is wrong because the passage is last year's. Faithful? Correct?

    Faithful (the claim is supported by the passage it was given) but not correct. The fix is in retrieval or the corpus, not in the generator.

    2. Why are changed-number claims harder to reject than unrelated ones?

    They share almost every word with the premise, and small checkers lean heavily on overlap. A single digit is a small part of the input, so it can slip through as entailment. Unrelated claims share few words: both NLI models rejected all 23 here.

    3. How would you test a faithfulness metric before relying on it?

    Build pairs with known labels: true claims against their source, and the same claims perturbed (numbers changed, negated, entities swapped) or checked against the wrong passage. Measure how often the metric accepts each kind, as above, then spot-check its verdicts on real answers by hand.
