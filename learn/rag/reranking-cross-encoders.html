    Reranking with cross-encoders

    A reranker takes the top candidates from a fast retriever and re-scores each one with a cross-encoder, a model that reads the question and the passage together, then keeps the best few. It is slower per passage than an embedding search, so it only sees a short candidate list, but it judges relevance much better. On 80 questions about IRS Publication 17, reranking the top 30 hybrid candidates with ms-marco-MiniLM-L-6-v2 put the answer passage first for 54 questions, against 40 without it (p = 0.007), and in the top 5 for 72 against 67 (suggestive, p = 0.18).

    Runs on: CPU, about two minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · rank-bm25 0.2.2 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    Retrieve fast, then rerank

    An embedding model (a bi-encoder) compresses the passage into one vector before it has seen the question. That is what makes it fast, and also what limits it: whatever the vector dropped, the search can't use. A cross-encoder takes the question and the passage as one input, lets every word of each attend to the other, and outputs a single relevance score. It can notice that a passage mentions "Roth IRA" when the question asks about a traditional one.

    The price is one full model pass per (question, passage) pair, with nothing precomputable. So the usual pipeline has two stages:

    1. Retrieve a candidate pool, 20 to 100 passages, with BM25, dense or hybrid search. This stage decides recall: the reranker can't rescue a passage that isn't in the pool.
    2. Rerank the pool with the cross-encoder and keep the top few. This stage decides order: what lands first.

    The model below, cross-encoder/ms-marco-MiniLM-L-6-v2, is a 6-layer MiniLM trained on MS MARCO web-search pairs (Apache-2.0).

    from sentence_transformers import CrossEncoder

reranker = CrossEncoder("cross-encoder/ms-marco-MiniLM-L-6-v2", device="cpu",
                        revision="233902d25c440f23af6f7d6e94d2946bac0bee0a")
docs = ["You can open a traditional IRA at any time.",
        "A Roth IRA contribution is not deductible.",
        "The standard deduction for a single filer."]
query = "Can I deduct a traditional IRA contribution?"
for doc, score in zip(docs, reranker.predict([(query, d) for d in docs])):
    print(f"{score:7.3f}  {doc}")

    Measured: pool size, recall and time on IRS Publication 17

    Same corpus, 512-character chunks and 80 frozen questions as the other RAG pages (30 + 50); a chunk is relevant when it holds the whole evidence span, and 79 is the ceiling.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Output

    sha256: 2d2381d62c7c77ed | chunks: 2170 | questions: 80 | with a relevant chunk: 79

    Setup. The hybrid ranking from the hybrid search page (BM25 and all-MiniLM-L6-v2 fused by RRF, k = 60) supplies the candidates. The cross-encoder scores the top 50 once per question; a pool of N keeps the N best-ranked candidates and reorders them by score. The BM25-only row is the shape BrewSLM uses when a reranker is switched on. MRR is the mean of 1 / (rank of the first relevant chunk) within the top 10.

    import math, time
import numpy as np
from sentence_transformers import SentenceTransformer
from rank_bm25 import BM25Okapi

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
vecs = model.encode([c.strip() for c in chunks], normalize_embeddings=True, batch_size=64)
dense = np.argsort(-(model.encode([q["question"] for q in qs], normalize_embeddings=True) @ vecs.T), axis=1)
words = lambda s: re.findall(r"[a-z0-9]+", s.lower())
bm25 = BM25Okapi([words(c) for c in chunks])
lexical = np.array([np.argsort(-bm25.get_scores(words(q["question"]))) for q in qs])

def rrf(rankings, k=60):
    score = {}
    for ranking in rankings:
        for rank, doc in enumerate(ranking, start=1):
            score[doc] = score.get(doc, 0.0) + 1.0 / (k + rank)
    return sorted(score, key=lambda d: -score[d])

hybrid = [rrf([lexical[i][:100], dense[i][:100]]) for i in range(len(qs))]

ce = {}                                     # (question, chunk) -> cross-encoder score
t0 = time.time()
for i, q in enumerate(qs):
    pool = list(dict.fromkeys(list(hybrid[i][:50]) + list(lexical[i][:30])))
    for j, s in zip(pool, reranker.predict([(q["question"], chunks[j]) for j in pool], batch_size=32)):
        ce[i, j] = float(s)
per_pair = (time.time() - t0) / len(ce) * 1000

def rerank(ranked, n):
    return [sorted(ranked[i][:n], key=lambda j: -ce[i, j]) for i in range(len(qs))]

def found(ranked, k):
    return [bool(set(list(ranked[i])[:k]) & gold[i]) for i in range(len(qs))]

def mrr(ranked):
    return np.mean([next((1 / r for r, j in enumerate(ranked[i][:10], 1) if j in gold[i]), 0) for i in range(len(qs))])

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.4f}"

runs = {"hybrid, no rerank": hybrid}
for n in (10, 20, 30, 50):
    runs[f"hybrid top {n}, reranked"] = rerank(hybrid, n)
runs["bm25 top 30, reranked"] = rerank(lexical, 30)
print("candidates               top 1  top 5   MRR@10   CPU per question")
for name, r in runs.items():
    n = int(name.split("top ")[1].split(",")[0]) if "top" in name else 0
    cost = f"{n * per_pair:.0f} ms" if n else "-"
    print(f"{name:<24} {sum(found(r, 1)):>5}  {sum(found(r, 5)):>5}   {mrr(r):.3f}   {cost}")
print("\npool 30 reranked vs no rerank, top 1:", mcnemar(found(runs["hybrid top 30, reranked"], 1), found(hybrid, 1)))
print("pool 30 reranked vs no rerank, top 5:", mcnemar(found(runs["hybrid top 30, reranked"], 5), found(hybrid, 5)))
print("hybrid pool 30 vs bm25 pool 30, top 5:", mcnemar(found(runs["hybrid top 30, reranked"], 5), found(runs["bm25 top 30, reranked"], 5)))
print("relevant chunk inside the pool of 30: hybrid", sum(bool(set(hybrid[i][:30]) & gold[i]) for i in range(len(qs))),
      "| bm25", sum(bool(set(lexical[i][:30]) & gold[i]) for i in range(len(qs))))

relevant chunk inside the pool of 30: hybrid 76 | bm25 74
    • The reranker mostly fixed the order. Answer passage ranked first: 40 of 80 without reranking, 54 with a pool of 30. Nineteen questions moved up to first and five moved down (exact McNemar, p = 0.007), and MRR@10 rose from 0.64 to 0.77.
    • Top 5 rose less, from 67 to 72 (7 against 2, p = 0.18): suggestive. Most answer passages were already in the hybrid top 5, just not first.
    • A pool of 20 was enough here. 10 candidates gave 69 at top 5; 20, 30 and 50 all gave 72, while the cost grew linearly, one model pass per candidate.
    • After reranking, the first stage mattered little. A BM25-only pool of 30 held the relevant chunk for 74 questions against the hybrid pool's 76, and once reranked the two ended level (71 and 72 at top 5, 55 and 54 first). The reranker absorbed most of what fusion had added. The pool's own recall is still the ceiling: no reranker can lift a passage that isn't in it.

    Limits: one document, one small reranker trained on web search rather than tax text, and 80 single-fact questions drafted with an AI assistant. Pool sizes were compared on the same questions they are reported on. The timing is for this 20-core CPU with batch size 32.

    Pitfalls

    • Treating scores as probabilities. This model outputs logits. A fixed cut-off such as "keep scores above 0" depends on the model and the domain; this model's config sets an identity activation, so predict returns logits, while other single-label cross-encoders get a sigmoid by default (sentence-transformers cross-encoder docs). Check which you have before thresholding.
    • A pool too small to matter. With a pool of 10 the reranker reached 69 at top 5, three short of larger pools (table above). Check the pool's own recall before blaming the reranker.
    • Latency surprises. 30 candidates mean 30 model passes per question. On CPU that is fine for a demo, not for high traffic. BrewSLM caps an explicit pool at 100 so one reranking call stays a few seconds on CPU (retrieval_reranker.py).
    • A stronger reranker is not always better downstream. In BrewSLM's Pub 17 run, answer quality with the MiniLM reranker went from 0.61 (top 5, no reranker) to 0.55, while a larger bge reranker reached 0.67 (IRS Pub 17 post). Measure answers, not only retrieval.

    In BrewSLM: retrieval is BM25 top 3 by default; the documents → Q&A sweep can add this MiniLM cross-encoder or a larger one, over a pool of 4 × k (10 to 40).

    Practice

    1. Reranking raised top-1 a lot but top-5 only a little. What does that tell you about the first stage?

    The first stage was already putting the answer passage near the top, just not first. The reranker's value here is order. If top-5 had been low too, the problem would be recall, and a better first stage or a bigger pool would matter more than the reranker.

    2. A pool of 50 takes about 1.7 times as long to rerank as a pool of 30. Why not always use 50?

    Because past 20 there was no gain here, and the cost is paid on every question. Pick the smallest pool where recall inside the pool stops rising, then confirm the top-k you keep doesn't change.

    3. Why can't you build a cross-encoder index ahead of time?

    Its score is a function of the question and the passage read together. There is no per-passage vector to store; every new question needs fresh passes over its candidates.
