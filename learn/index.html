BrewSLM Learn: applied AI, one topic per page

Short pages you can land on from a search, read in a few minutes and run on a laptop. Each one answers one question about retrieval, embeddings, evaluation, serving or the libraries around them. The Academy is where the ordered courses live; these pages are for looking one thing up.

How the pages are made

  • The code was run, not described. Every runnable block was executed before publishing, and the box under it is what it printed. Each page says the date, the library versions and that it ran on CPU, and the blocks are rerun by a script before publishing (by hand for now, not in CI); check fails if the code, the output or the data changed since the last passing run.
  • A measured number where there is one. The RAG and embeddings pages measure on one shared corpus, IRS Publication 17, with 80 questions frozen before any run and published next to the pages, so a number on one page can be compared with a number on another. Differences are tested on the same questions, and called suggestive when the test can't separate them.
  • Pitfalls with a source. Each one links to a model card, a file in the BrewSLM repo, a post or an output on the page.
  • Open-source tools, small and local. sentence-transformers, rank-bm25, FAISS, scikit-learn and pypdf, open embedding and reranking models pinned to a revision, and a 1.5B open model served by Ollama on CPU for the pages that generate answers. Each page names its models' licences. No API keys and no GPU.
