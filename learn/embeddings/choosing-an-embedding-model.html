    Choosing an embedding model: test on your own documents

    Pick two to five open models that fit your licence, language, input length and hardware, then measure them on a few dozen of your own queries with known answers; leaderboard rank on public benchmarks is a starting point, not a decision. Check each model's card for required query prefixes and its score function, since getting them wrong fails silently. On 80 questions about IRS Publication 17, the six models tested found between 57 and 69 answers in their top 5: the most-downloaded model, all-MiniLM-L6-v2, came last, and bge-base-en-v1.5 came first at about a quarter of its speed on CPU.

    Runs on: CPU, about fifteen minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    What to compare

    Embedding models differ in more than quality, and several differences rule a model out before any measurement:

    • Licence. Apache-2.0 and MIT allow commercial use; some popular models are research-only or carry use restrictions. Read the model card, not a summary.
    • Language and domain. English-only models fail quietly on other languages; code and legal text behave differently from web text.
    • Input length. 256 to 512 word pieces for most small models; your chunks have to fit (sentence-transformers basics).
    • Size and speed. Encoding the corpus is a one-off; encoding each query is on the critical path, and on a CPU a 109M-parameter model is several times slower than a 23M one.
    • Dimensions. Memory per vector; see dimensions vs quality.
    • How it expects to be called. Query prefixes or instructions, and cosine or dot product (cosine, dot and L2).

    Public benchmarks such as MTEB average many tasks and domains. They narrow the list; they don't tell you how a model ranks passages of your documents.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    Measured: six models, one corpus, 80 questions

    Setup. The shared corpus: IRS Publication 17 (2025) in 2,170 chunks of up to 512 characters, 80 frozen questions (30 + 50), and a question counts as found when one of its top 5 chunks holds the whole evidence span. Six open models at pinned revisions, all small enough for a CPU, all Apache-2.0 or MIT. bge models get their documented query instruction and e5 its "query: " and "passage: " prefixes; each of those three is also run without them. Speed is chunks encoded per second on this machine, which was busy with other work, so compare speeds with each other rather than reading them as absolute.

    import math, time
import numpy as np
from sentence_transformers import SentenceTransformer

BGE = "Represent this sentence for searching relevant passages: "
candidates = [  # name, repo, revision, licence, query prefix, passage prefix
    ("all-MiniLM-L6-v2", "sentence-transformers/all-MiniLM-L6-v2", "1110a243fdf4706b3f48f1d95db1a4f5529b4d41", "Apache-2.0", "", ""),
    ("bge-small-en-v1.5", "BAAI/bge-small-en-v1.5", "5c38ec7c405ec4b44b94cc5a9bb96e735b38267a", "MIT", BGE, ""),
    ("e5-small-v2", "intfloat/e5-small-v2", "ffb93f3bd4047442299a41ebb6fa998a38507c52", "MIT", "query: ", "passage: "),
    ("gte-small", "thenlper/gte-small", "17e1f347d17fe144873b1201da91788898c639cd", "MIT", "", ""),
    ("all-mpnet-base-v2", "sentence-transformers/all-mpnet-base-v2", "e8c3b32edf5434bc2275fc9bab85f82640a19130", "Apache-2.0", "", ""),
    ("bge-base-en-v1.5", "BAAI/bge-base-en-v1.5", "a5beb1e3e68b9ab74eb54cfd186867f64f240e1a", "MIT", BGE, ""),
]

def evaluate(Q, D):
    ranked = np.argsort(-(Q @ D.T), axis=1)
    found = [bool(set(ranked[i, :5]) & gold[i]) for i in range(len(qs))]
    rr = [next((1 / (r + 1) for r, j in enumerate(ranked[i, :100]) if j in gold[i]), 0.0) for i in range(len(qs))]
    return found, float(np.mean(rr))

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.3f}"

docs = [c.strip() for c in chunks]
questions = [q["question"] for q in qs]
results = {}
print(f"{'model':<20}{'params':>8}{'dims':>6}{'top 5':>8}{'MRR':>7}  {'licence':<12}chunks/s")
for name, repo, rev, lic, qp, dp in candidates:
    m = SentenceTransformer(repo, device="cpu", revision=rev)
    params = sum(p.numel() for p in m.parameters()) / 1e6
    t0 = time.time()
    D = m.encode([dp + d for d in docs], batch_size=32, normalize_embeddings=True)
    rate = len(docs) / (time.time() - t0)
    found, mrr = evaluate(m.encode([qp + q for q in questions], normalize_embeddings=True), D)
    results[name] = found
    print(f"{name:<20}{params:>7.0f}M{D.shape[1]:>6}{sum(found):>5}/80{mrr:>7.3f}  {lic:<12}{rate:.0f}")
    if qp:                                                   # the same model without its query prefix
        found_np, mrr_np = evaluate(m.encode(questions, normalize_embeddings=True),
                                    m.encode(docs, batch_size=32, normalize_embeddings=True) if dp else D)
        results[name + " (no prefix)"] = found_np
        print(f"{'  without prefixes':<20}{'':>8}{'':>6}{sum(found_np):>5}/80{mrr_np:>7.3f}")

best = max(candidates, key=lambda c: (sum(results[c[0]]), c[0]))[0]
print(f"\nbest vs all-MiniLM-L6-v2 ({best}): {mcnemar(results[best], results['all-MiniLM-L6-v2'])}")
for name in ("bge-small-en-v1.5", "e5-small-v2"):
    print(f"{name}, prefixes vs none: {mcnemar(results[name], results[name + ' (no prefix)'])}")

    • The default came last. all-MiniLM-L6-v2, the usual first choice and the model the other pages here use for comparability, found 57. The three 33M-parameter models found 65 to 67, and bge-base-en-v1.5 found 69, gaining 12 questions over MiniLM and losing none (exact McNemar p < 0.001).
    • Bigger was not reliably better. all-mpnet-base-v2, at 109M parameters, found 65, fewer than gte-small at 33M. bge-base beat the best small models by two questions, which is noise at this size.
    • Prefixes mattered for one model and not the other. bge-small without its query instruction found 62 instead of 67 (5 against 0, p = 0.062, suggestive). e5-small did slightly better without its prefixes here (67 against 65, 2 against 0), the opposite of what its card leads you to expect, and too small a difference to read anything into.
    • Speed fell with size: the 109M models encoded about a quarter as many chunks per second as MiniLM on this CPU.

    Limits: one English document, 80 short-answer questions, six models from the small end. The ranking between the 65-to-69 group is not settled by 80 questions; the gap between MiniLM and the best model (12 vs 0) is.

    A short procedure

    StepWhat to doHere
    1. FilterLicence, language, input length, size that your hardware serves fast enough.English, ≤ 110M, Apache-2.0 or MIT
    2. Label30 to 100 real queries, each with the passage or span that answers it.80 frozen questions
    3. MeasureRecall at the k you will use, MRR, query latency, with each model called as its card says.Top 5, MRR, chunks/s
    4. Compare pairedMcNemar or a bootstrap on the same queries; treat a gap of two or three as a tie.Last lines of the output
    5. PinRecord the revision and re-embed everything if you change it.revision=

    Pitfalls

    • Choosing by downloads. The most-used model came last here, eight questions behind the next one and twelve behind the best. Popularity reflects age and defaults in tutorials, not fit to your data; measure (table above).
    • Forgetting the query instruction. bge's card lists a query instruction for retrieval and says the v1.5 models need it less (bge-small model card); here, without it, bge-small found five fewer. Nothing errors when you forget.
    • Trusting a prefix rule without testing it. e5's card says to use "query: " and "passage: " (e5-small-v2 model card), yet here it scored a little better without them. Follow the card by default and measure both when you can.
    • Leaderboard averages. The MTEB leaderboard averages dozens of tasks; a model's retrieval score on your domain can differ from its rank there.

    In BrewSLM: the dataset diagnostics use all-MiniLM-L6-v2, a choice for speed on CPU rather than retrieval quality; passage retrieval itself uses BM25 and an optional cross-encoder (reranking).

    Practice

    1. Model A finds 67 of 80 and model B 65 of 80 on your queries. Which do you pick?

    On those numbers alone it's a tie: a two-question gap on 80 rarely passes a paired test. Decide on the other criteria (speed, licence, dimensions, input length), or label more queries.

    2. Why run a model both with and without its prefixes?

    To learn whether your pipeline is calling it correctly and how much it matters for your data. Here the bge instruction was worth five questions and the e5 prefixes nothing; without the comparison you wouldn't know either.

    3. Query latency matters more than indexing speed. Why?

    The corpus is embedded once, offline, and can be batched; each query is embedded while a user waits. A model four times slower adds that factor to every search.
