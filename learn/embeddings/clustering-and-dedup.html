    Clustering and deduplication with embeddings

    To find near-duplicates, embed every text, compute the cosine similarity of every pair and flag pairs above a threshold; to cluster, run an algorithm such as k-means on the same vectors. Both depend on choices the data has to settle: the threshold, the number of clusters, and what the model treats as similar. On IRS Publication 17's 2,170 chunks, only 2 were exact duplicates but 69 pairs scored above 0.98, and k-means with 14 clusters matched the 14 chapters only partly (adjusted Rand index 0.28, about the same as word-count vectors gave).

    Runs on: CPU, about two minutes for every block on the page once the model is downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · scikit-learn 1.9.1 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    Two uses of the same similarity matrix

    Once texts are vectors, "which texts are nearly the same?" and "which texts belong together?" are both questions about distances.

    • Deduplication looks at the extreme top of the similarity distribution. Exact duplicates are found faster with a hash; embeddings add near-duplicates that differ in spacing, a few words, or a page header. The decision is a threshold.
    • Clustering groups the whole collection. k-means picks k centres and assigns every vector to the nearest; on normalised vectors that is grouping by direction. The decisions are k and whether the clusters mean anything.

    Both are common data-cleaning steps before training: duplicates inflate some examples' weight and leak between train and test splits, and clusters show what a dataset is mostly about.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    import hashlib
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("sentence-transformers/all-MiniLM-L6-v2", device="cpu",
                            revision="1110a243fdf4706b3f48f1d95db1a4f5529b4d41")
docs = [" ".join(c.split()) for c in chunks]
V = model.encode(docs, batch_size=64, normalize_embeddings=True)
S = V @ V.T
iu = np.triu_indices(len(docs), k=1)                   # each pair once
pair_sims = S[iu]

exact = len(docs) - len({hashlib.sha256(d.lower().encode()).hexdigest() for d in docs})
print("exact duplicates (after lowercasing and joining whitespace):", exact)
print(f"{'threshold':<11}{'pairs above':>12}{'chunks involved':>17}")
for t in (0.98, 0.95, 0.92, 0.90, 0.85):
    hit = pair_sims >= t
    print(f"{t:<11}{int(hit.sum()):>12}{len(set(iu[0][hit]) | set(iu[1][hit])):>17}")

digit_share = lambda d: sum(ch.isdigit() for ch in d) / max(1, sum(not ch.isspace() for ch in d))
near = sorted(set(iu[0][pair_sims >= 0.95]) | set(iu[1][pair_sims >= 0.95]))
tabular = sum(digit_share(docs[j]) > 0.5 for j in near)
print(f"of the {len(near)} chunks in a pair at 0.95 or above, {tabular} are mostly digits (tax-table rows);"
      f" in the whole corpus, {sum(digit_share(d) > 0.5 for d in docs)}")

def show(lo, hi):
    k = int(np.flatnonzero((pair_sims >= lo) & (pair_sims < hi))[0])
    a, b = iu[0][k], iu[1][k]
    print(f"\n{pair_sims[k]:.3f}  chunk {a}: {docs[a][:100]}\n       chunk {b}: {docs[b][:100]}")
show(0.98, 1.01)
show(0.92, 0.93)

    Two exact duplicates, but many more pairs above any high threshold. The examples show the range: at 1.000 the same sentence printed twice in the publication (once near the front, once in its chapter); around 0.93, two passages about the same online-account features, overlapping but not the same text; at 0.85, neighbouring passages on related topics that nobody would call duplicates. Where to draw the line depends on what a duplicate means for your use: for train/test leakage, err low and read the pairs; for removing repeats, err high.

    Most of the high-similarity pairs are not prose at all. Of the 176 chunks in a pair at 0.95 or above, 146 are mostly digits: rows of the tax tables, which to a sentence model all look alike. The corpus has 171 such chunks, and nearly all of them land in the near-duplicate set. A dedup pass with this threshold would delete most of the tax tables, which are not duplicates of each other at all. Structured text needs its own rule (exact match on the row, or leave it out of the semantic check).

    Measured: do k-means clusters find the chapters?

    Setup. Publication 17's page footers name the chapter, which gives a label for every chunk on a chapter page (1,705 of 2,170; the front matter, tax tables and index are left out). k-means with k = 14, one cluster per chapter, runs on the MiniLM vectors and, for comparison, on TF-IDF vectors of the same chunks. Agreement with the chapters is measured by the adjusted Rand index (ARI: 0 for chance, 1 for identical groupings) and normalised mutual information (NMI); a shuffled labelling shows the chance level.

    from collections import Counter
from sklearn.cluster import KMeans
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.metrics import adjusted_rand_score, normalized_mutual_info_score

pages = text.split("\n\n")
FOOTER = re.compile(r"Chapter (\d+) [A-Z]")
chunk_page = [text.count("\n\n", 0, s) for s in starts]
chapter = [(m.group(1) if (m := FOOTER.search(pages[p])) else None) for p in chunk_page]
keep = [j for j, c in enumerate(chapter) if c]                 # chunks on a page with a chapter footer
labels = [chapter[j] for j in keep]
k = len(set(labels))
print(len(keep), "chunks in", k, "chapters; largest", Counter(labels).most_common(1)[0][1], "smallest",
      Counter(labels).most_common()[-1][1])

tfidf = TfidfVectorizer(sublinear_tf=True, stop_words="english").fit_transform([docs[j] for j in keep])
rng = np.random.default_rng(0)
arms = {"embeddings (MiniLM)": V[keep], "TF-IDF": tfidf}
print(f"\n{'k-means on':<22}{'ARI':>7}{'NMI':>7}")
for name, X in arms.items():
    pred = KMeans(n_clusters=k, n_init=10, random_state=0).fit_predict(X)
    print(f"{name:<22}{adjusted_rand_score(labels, pred):>7.3f}{normalized_mutual_info_score(labels, pred):>7.3f}")
shuffled = rng.permutation(labels)
print(f"{'labels shuffled':<22}{adjusted_rand_score(labels, shuffled):>7.3f}{normalized_mutual_info_score(labels, shuffled):>7.3f}")

pred = KMeans(n_clusters=k, n_init=10, random_state=0).fit_predict(V[keep])
print("\nlargest chapter in each of the first five clusters (share of the cluster):")
for c in range(5):
    members = [labels[i] for i in np.flatnonzero(pred == c)]
    top, n = Counter(members).most_common(1)[0]
    print(f"  cluster {c}: {len(members):>3} chunks, chapter {top} ({n / len(members):.0%})")

    Pitfalls

    • Templated text looks like duplicates. Tables, forms and boilerplate share structure and vocabulary, so they crowd the top of the similarity distribution (output above). Inspect what sits above your threshold before deleting it.
    • A threshold from someone else's data. BrewSLM flags near-duplicate training rows at 0.92 with MiniLM; on this corpus 0.92 flags 4,604 pairs, mostly not duplicates in any useful sense. Calibrate by reading pairs at a few thresholds (dataset_intelligence_service.py).
    • Reading meaning into k-means clusters. k-means always returns k groups, whether or not they exist. Check against labels where you have them, as above, and sample members where you don't (scikit-learn clustering guide).
    • Dedup within train only. Duplicates between train and test are the ones that inflate scores; check across splits, not just inside one (BrewSLM data gates).

    In BrewSLM: the dataset diagnostics embed rows with all-MiniLM-L6-v2 and flag pairs at cosine 0.92 or above as near-duplicates, falling back to hashed vectors without the model (data gates).

    Practice

    1. Why hash first, then embed?

    Hashing finds exact duplicates in linear time and with no model; embedding and comparing all pairs is far more expensive. Remove the exact copies first so the embedding step only has to judge the near ones.

    2. k-means on your support tickets gives clusters with ARI 0.3 against the product labels. Is the clustering bad?

    Not necessarily. ARI measures agreement with one labelling; the clusters may follow another real structure (issue type rather than product). Sample tickets from each cluster before deciding, and compare with a TF-IDF baseline as above.

    3. How many pairs does an all-pairs check over 100,000 texts compare?

    100,000 × 99,999 ÷ 2 ≈ 5 billion. Use an approximate nearest-neighbour index and look only at each text's closest few.
