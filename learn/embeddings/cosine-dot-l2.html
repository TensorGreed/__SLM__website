    Cosine, dot product and L2 distance: which similarity, and when to normalise

    Cosine similarity compares only the direction of two vectors, the dot product also rewards length, and L2 (Euclidean) distance measures how far apart the points are; once every vector is normalised to length 1, all three rank results identically, since L2² = 2 − 2·cosine and the dot product equals the cosine. So the choice only matters for models whose vectors vary in length, and the right one is the one the model was trained with. On 80 questions about IRS Publication 17, all three gave the same top 5 with all-MiniLM-L6-v2, which normalises its output, while msmarco-distilbert-base-tas-b, trained for the dot product, found 66 with the dot product and 62 with cosine, a gap the paired test can't confirm (p = 0.39).

    Runs on: CPU, about three minutes for every block on the page once the models are downloaded Updated: 26 Nov 2026

    Tested on 26 Nov 2026 · Python 3.12.3 · sentence-transformers 3.3.1 · transformers 4.46.3 · torch 2.5.1 · pypdf 5.1.0 · numpy 2.1.3 · CPU (20-core Arm, no GPU)

    Three ways to compare two vectors

    For a query vector q and a document vector d:

    • Dot product, q · d: the sum of the products of matching coordinates. It grows with the angle getting smaller and with either vector getting longer.
    • Cosine similarity, q · d / (|q| |d|): the dot product of the two vectors scaled to length 1. It runs from −1 to 1 and ignores length entirely.
    • L2 distance, |q − d|: the straight-line distance between the two points. Smaller is closer, and it is sensitive to length as well as angle.

    Normalising means dividing each vector by its length so that every vector has length 1. After that, the dot product is the cosine, and |q − d|² = 2 − 2 cos(q, d), so L2 distance is a fixed decreasing function of cosine: the three give the same ranking. That is why many vector indexes offer only inner product or L2: normalise first, and either gives cosine ranking.

    The three on toy vectors

    import numpy as np

q = np.array([1.0, 0.0])
docs = {"a: same direction, short": np.array([0.5, 0.1]),
        "b: same direction, long": np.array([5.0, 1.0]),
        "c: other direction, long": np.array([3.0, 3.0])}
cos = lambda x, y: float(x @ y / (np.linalg.norm(x) * np.linalg.norm(y)))
print(f"{'':<26}{'cosine':>8}{'dot':>8}{'L2':>8}")
for name, d in docs.items():
    print(f"{name:<26}{cos(q, d):>8.3f}{float(q @ d):>8.3f}{float(np.linalg.norm(q - d)):>8.3f}")
unit = lambda x: x / np.linalg.norm(x)
print("\nafter normalising every vector:")
for name, d in docs.items():
    u = unit(d)
    print(f"{name:<26}{cos(q, u):>8.3f}{float(q @ u):>8.3f}{float(np.linalg.norm(q - u)):>8.3f}"
          f"   2 - 2*cos = {2 - 2 * cos(q, u):.3f}, L2^2 = {float(np.linalg.norm(q - u)) ** 2:.3f}")

after normalising every vector:
a: same direction, short     0.981   0.981   0.197   2 - 2*cos = 0.039, L2^2 = 0.039
b: same direction, long      0.981   0.981   0.197   2 - 2*cos = 0.039, L2^2 = 0.039

    Before normalising, the three disagree. Cosine scores a and b the same (0.981), since they point the same way. The dot product prefers b, five times longer, and even ranks c above a, though c points 45° away. L2 prefers a, simply because it sits close to the query. After normalising, a and b become the same point, every column agrees on the order, and the last two columns confirm L2² = 2 − 2·cos.

    Which behaviour you want depends on what length means. In a model trained with the dot product, length can carry information, such as how much relevant material a passage holds; in one trained with cosine, length is noise.

    Measured: two models, three similarities

    Setup. The corpus and frozen questions shared with the RAG pages: IRS Publication 17 (2025) in 2,170 chunks of up to 512 characters, 80 questions (30 + 50), and a chunk counts as relevant when it holds the question's whole evidence span. Two models at pinned revisions: all-MiniLM-L6-v2, trained with cosine and ending in a normalisation layer, and msmarco-distilbert-base-tas-b, a port of a model trained for the dot product (the original is named distilbert-dot-tas_b), whose card scores with util.dot_score. Vectors are taken raw (normalize_embeddings left off) and scored all three ways.

    import hashlib, json, os, re, urllib.request
from pypdf import PdfReader

if not os.path.exists("p17.pdf"):
    urllib.request.urlretrieve("https://www.irs.gov/pub/irs-prior/p17--2025.pdf", "p17.pdf")
FURNITURE = re.compile(r"^(Userid:|AH XSL/XML Fileid|Page \d+ of \d+|The type and rule above).*$", re.M)

def clean(page):
    page = FURNITURE.sub("", page)                  # proof-sheet lines on every page
    page = re.sub(r"-[ \t]*\n(?=[a-z])", "", page)  # re-join words hyphenated at line ends
    page = re.sub(r"\s*\n\s*", " ", page)
    return re.sub(r" {2,}", " ", page).strip()

def split_keep(text, sep):
    if sep == "":
        return list(text)
    parts = text.split(sep)
    return [p + sep for p in parts[:-1]] + ([parts[-1]] if parts[-1] else [])

def recursive_split(text, size, seps=("\n\n", "\n", ". ", " ", "")):
    if len(text) <= size:
        return [text]
    pieces = []
    for piece in split_keep(text, seps[0]):
        pieces += [piece] if len(piece) <= size else recursive_split(piece, size, seps[1:])
    chunks, buf = [], ""
    for p in pieces:                                # greedy packing, never over size
        if buf and len(buf) + len(p) > size:
            chunks.append(buf)
            buf = ""
        buf += p
    return chunks + [buf] if buf else chunks

text = "\n\n".join(clean(p.extract_text()) for p in PdfReader("p17.pdf").pages)
chunks = recursive_split(text, 512)
starts = [0]
for c in chunks[:-1]:
    starts.append(starts[-1] + len(c))

qs = [q for f in ("pub17-chunking-questions.json", "pub17-more-questions.json")
      for q in json.load(open(f))["questions"]]
gold = []                                           # chunks holding a whole evidence span
for q in qs:
    occ = [m.span() for m in re.finditer(re.escape(q["evidence"]), text)]
    gold.append({j for j, s in enumerate(starts) if any(s <= a and b <= s + len(chunks[j]) for a, b in occ)})
print("sha256:", hashlib.sha256(open("p17.pdf", "rb").read()).hexdigest()[:16], "| chunks:", len(chunks),
      "| questions:", len(qs), "| with a relevant chunk:", sum(map(bool, gold)))

    import math
from sentence_transformers import SentenceTransformer

models = {"all-MiniLM-L6-v2": ("sentence-transformers/all-MiniLM-L6-v2", "1110a243fdf4706b3f48f1d95db1a4f5529b4d41"),
          "msmarco-distilbert-base-tas-b": ("sentence-transformers/msmarco-distilbert-base-tas-b",
                                            "b12d9352e776979147078a8975a4885042984fd1")}

def scores(Q, D, kind):
    if kind == "dot":
        return Q @ D.T
    if kind == "cosine":
        return (Q / np.linalg.norm(Q, axis=1, keepdims=True)) @ (D / np.linalg.norm(D, axis=1, keepdims=True)).T
    return -np.sqrt(((Q ** 2).sum(1)[:, None] + (D ** 2).sum(1)[None, :] - 2 * Q @ D.T).clip(0))   # -L2: higher is closer

def evaluate(S):
    ranked = np.argsort(-S, axis=1)
    found = [bool(set(ranked[i, :5]) & gold[i]) for i in range(len(qs))]
    rr = [next((1 / (r + 1) for r, j in enumerate(ranked[i, :100]) if j in gold[i]), 0.0) for i in range(len(qs))]
    top1_len = np.mean([len(chunks[ranked[i, 0]]) for i in range(len(qs))])
    return found, np.mean(rr), top1_len, ranked

def mcnemar(x, y):
    b = sum(p and not q for p, q in zip(x, y))
    c = sum(q and not p for p, q in zip(x, y))
    p = min(1.0, 2 * sum(math.comb(b + c, i) for i in range(min(b, c) + 1)) / 2 ** (b + c))
    return f"{b} vs {c}, p = {p:.3f}"

lengths = np.array([len(c) for c in chunks])
for name, (repo, rev) in models.items():
    m = SentenceTransformer(repo, device="cpu", revision=rev)
    D = m.encode([c.strip() for c in chunks], batch_size=64)          # raw output, no normalisation
    Q = m.encode([q["question"] for q in qs])
    norms = np.linalg.norm(D, axis=1)
    corr = f"; correlation of length with chunk characters {np.corrcoef(norms, lengths)[0, 1]:+.2f}" \
        if norms.std() > 1e-3 else " (the model normalises its own output)"
    print(f"\n{name}: vector length min {norms.min():.2f}, max {norms.max():.2f}{corr}")
    print(f"  {'score':<8}{'found in top 5':>16}{'MRR':>8}{'top-1 chunk chars':>20}")
    ranks, hits = {}, {}
    for kind in ("dot", "cosine", "L2"):
        hits[kind], mrr, t1, ranks[kind] = evaluate(scores(Q, D, kind))
        print(f"  {kind:<8}{sum(hits[kind]):>13}/80{mrr:>8.3f}{t1:>20.0f}")
    same = (ranks["cosine"][:, :5] == ranks["L2"][:, :5]).all()
    print("  cosine and L2 give identical top 5 for every question:", bool(same))
    print("  dot vs cosine:", mcnemar(hits["dot"], hits["cosine"]))

    • With a normalising model the choice doesn't matter. MiniLM's vectors all have length 1.00, and dot, cosine and L2 gave the same top 5 for every question: 57 of 80 found, MRR 0.579.
    • With a dot-product model it does. tas-b's vector lengths ranged from 10.4 to 11.9, and longer chunks tended to get longer vectors (correlation +0.15). Scored with the dot product, as trained, it found 66 of 80 (MRR 0.688); normalised to cosine, 62 (0.653); L2, 61. The paired comparison on the last line is 8 questions against 4, p = 0.39: the direction matches how the model was trained, but 80 questions can't confirm it.
    • Cosine and L2 still differ on unnormalised vectors: for tas-b their top 5 lists were not identical. They only coincide once vectors have length 1.

    Also visible: tas-b, trained on MS MARCO search queries, beat MiniLM here by nine questions. That is a model choice, not a similarity choice; see choosing an embedding model. Limits: two models, one corpus, 80 questions.

    Variations and parameters

    SituationUseWhy
    The model card says cosine, or the model ends in a Normalize layerNormalise, then dot product (fastest)Identical ranking to cosine
    The model card says dot product (tas-b, some msmarco models)Raw dot productLength carries signal the model learned to use
    The index only supports L2Normalise firstL2 on unit vectors ranks like cosine
    Clustering with k-meansNormalise firstk-means uses L2; unit vectors make it cluster by direction
    Fixed similarity thresholds (dedup)CosineBounded in [−1, 1], so a threshold means the same for short and long texts

    Pitfalls

    • Normalising a dot-product model. It cost tas-b four questions here (not significant on 80, but in the direction you'd expect). Check which score function the model card uses before turning on normalize_embeddings; tas-b's card uses the dot product (tas-b model card).
    • Normalising one side only. If documents are normalised at index time and queries aren't (or the reverse), scores shift by a per-query factor; rankings survive for the dot product but thresholds don't. Do the same thing on both sides; the normalize_embeddings argument does it per call (sentence-transformers basics).
    • Mixing metrics in the index. An index built for inner product but given unnormalised vectors from a cosine model ranks by length too. FAISS's guide on metric types says to normalise for cosine.
    • Reading L2 as similarity. L2 is a distance: smaller is closer. Sorting it the wrong way returns the least similar documents, and nothing errors; the measurement negates it so that higher is closer for all three.

    In BrewSLM: embeddings are normalised and compared by cosine for the dataset diagnostics' near-duplicate check (clustering and dedup).

    Practice

    1. Two unit vectors have cosine similarity 0.8. What is their L2 distance?

    L2² = 2 − 2 × 0.8 = 0.4, so L2 = √0.4 ≈ 0.632.

    2. Your index supports only inner product. Your model was trained with cosine. What do you do?

    Normalise every document vector before adding it and every query vector before searching. The inner product of unit vectors is the cosine, so the ranking is exactly cosine ranking.

    3. Why might a dot-product model rank long chunks higher, and is that bad?

    Its vector length can grow with how much matching content a text holds, as with tas-b here (lengths correlated +0.15 with chunk size). That is what it was trained to do and it scored best with the dot product; but if your chunks vary a lot in length, check that it isn't simply favouring the longest ones.
