BrewSLM docs

The rules BrewSLM runs by, read from the code rather than remembered. Each page names the commit it was checked against and the files it came from, and uses numbers from our own runs, including the ones that went badly. The Academy teaches the ideas; these pages say exactly what the product does with them.

  • Workspace map: where everything lives

    The six project sections, the Data steps, Train's More options, the Results tabs, the Ship stages and Settings, with the exact labels.

  • Data gates: leakage, splits, review and contamination

    Answer-key and split leakage at 0.9 word overlap, dedup at split, keeping the test set, the review queue, benchmark contamination and the one hard gate at Train.

  • Documents → Q&A, and the check that runs before training

    How the flow sizes its test set, the three retrieval tiers, and what happened on IRS Publication 17 when we trained anyway.

  • Training defaults, and why they are what they are

    LoRA targets by model size, auto epochs aiming at 200 steps, when gradient checkpointing turns on, precision, determinism and the OOM ladder.

  • Scoring modes: how each task shape is scored

    Exact match and F1, the answer judge and its calibration, typed JSON fields, strict spans, tool calls and SQL execution.

  • The lift check: is the fine-tune better than its base?

    The automatic base-vs-fine-tuned eval, the paired interval and McNemar guard, seeds and prompt-format variants, with real verdicts from our runs.

  • Export formats and what each one needs

    GGUF, Hugging Face, ONNX, TensorRT and Docker: package contents, tools to install, adapter merging and the Modelfile that keeps the evaluated decoding.

  • The brewslm command line

    Command groups and the flags that matter, read from the CLI's parser: login, demos, training, evals, export and serving.

Found something here that doesn't match the app? That is a bug in one of the two. Please open an issue. For the concepts behind these pages, start with the Academy; for whole projects, read the blog.
